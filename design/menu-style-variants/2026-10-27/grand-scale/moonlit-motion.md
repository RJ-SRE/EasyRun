# 静水圣庭 · 主菜单动态设计

2026-10-27。用户已选择 B「静水圣庭」。本文件定义下一步的美术与交互实现，不表示动画已完成；当前游戏和 v0.15.9 导入包尚未替换。

选定构图：[静水圣庭](b-moonlit-sanctuary.png)。保持小主角、巨大拱门、冷色云雾和浅水倒影，左上标志与右侧控件保持可读。画面尺寸与哈希见 [选择记录](selected.json)。

## 核心体验

圣庭很大、很静，旅人只是其中一个正在准备出发的身影。角色动作引起水面反馈，远处的微光引起角色注意，让世界与角色发生联系。建筑保持坚实静止，环境变化细微而持续。

画面同时只突出一件事：角色收线时，涟漪成为局部焦点；角色停下时，远景云雾才更容易被注意。避免所有元素同频摆动或一起发光。

## 动态分层

| 层次                 | 表现                                         | 节奏 / 强度目标                                            |
| -------------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 建筑、台阶、标志、UI | 固定空间位置，清晰稳定                       | 不加整图平移、缩放、呼吸或菜单镜头震动                     |
| 角色基础待机         | 半跪支撑，身体轻呼吸；围巾末端和衣摆小幅摆动 | 一直存在；支撑脚与膝盖落点稳定，动作不越出台阶             |
| 手与钩索             | 缓慢收起一小段绳线，检查绳头，重新放低       | 约 3–4 秒；手、绳端与水面位置连续，有可读的臂部轮廓变化    |
| 水滴与涟漪           | 绳头离水时带起少量水滴，滴落处产生椭圆波纹   | 落水事件触发，最多两组同时可见；约 2–3 秒淡出              |
| 水面反光             | 浅水表面有缓慢横向的明暗变化，倒影略微破碎   | 幅度低，保留直立建筑的稳定轮廓；不让整个倒影像橡胶一样摆动 |
| 门洞与水上薄雾       | 一层横过水面，一层穿过远处门洞               | 速度不同、连续缓慢；不扫过标题和控件造成可读性变化         |
| 远处塔窗             | 极少数窗格缓慢出现或减弱暖光                 | 偶发一次，亮起 / 熄弱各约 1–2 秒；无闪电和高频闪烁         |
| 近景植物 / 浮尘      | 少量茎叶响应与围巾相同的风势，少量浮尘漂移   | 可关闭的次要层，不遍布屏幕、不增加拥挤感                   |

角色在当前构图中很小。优先让抬臂、躯干倾斜和围巾轮廓可见，手指微动只作美术细节，不能依赖它表达“角色在动”。仍需在实际窗口中评估动作是否能被看见。

## 三组主角行为

### 1. 收索试水：标志动作

半跪静候 → 肩肘先抬、手收线 → 钩尖离开水面 → 一两滴水落下 → 涟漪展开 → 低头检查钩头 → 手慢慢放回。

约 3–4 秒，保持膝盖和支撑脚位置。绳索端点由角色动作驱动，水滴与涟漪由真实接触事件触发，不能各自循环后出现手已收回而绳线仍留在水中的情况。

### 2. 察看远门：环境回应

远处门洞旁的一扇小窗慢慢亮起 → 主角停止手边动作 → 面具抬起、肩部略转 → 看向远门片刻 → 恢复半跪待机。

约 2.5–3.5 秒。不加入敌人或跳脸演出，不要求玩家回应，不把它做成必须完成的剧情。

### 3. 调整护腕：出发准备

收回手臂 → 另一只手扣紧机械护腕 → 半起身调整重心 → 确认线轴固定 → 回到支撑姿势。

约 3–4 秒。起落高度要适合小角色的可读性，同时保持人物比例和落点连续。作为比“收索试水”更低频的变化，不要不断站起又蹲下。

## 行为调度

- 基础呼吸和衣料风动始终低幅运行；每隔约 12–20 秒有机会触发一段主行为，不连续重复同一段。
- 第一段“收索试水”可在进入菜单约 4–7 秒后发生，让用户较早察觉画面有生命。进入游戏无需等待它完成。
- 示例体验：先看到衣料和水雾 → 收索产生涟漪 → 一段安静 → 远门微光引起抬头 → 安静 → 整理护腕。该顺序用于理解节奏，不强制每次重播相同时间线。
- 主行为同时最多一个。设置抽屉或词册打开时只保留基础待机和低速环境变化，暂停触发新的主行为，降低阅读干扰。
- 主行为被“开始”打断时衔接最近的收手 / 起身姿态，不瞬间跳到完全相反的动作。快速返回标题也有明确初始化姿态，不继承战斗动量或震屏。

## UI 与开始过渡

标题保持静止，可用少量固定边缘高光表现材质，不做周期性亮灭。普通控件的悬停反馈仅改变描边和底色，目标过渡 120–180ms；尺寸与点击区域不跳动。

鼠标停留“进入钟城”约 350ms 或键盘聚焦该按钮时，可让主角轻抬头，手搭上钩索柄。单次进入焦点只响应一次；快速扫过按钮不触发完整动作，离开焦点也不倒放动作。

点击开始立即登记输入并给出按钮反馈。建议过渡为：收起钩索 → 起身面向巨门 → 短淡出接入关卡，总时长目标 0.7–0.9 秒，可通过 Enter 跳过。正式加载未就绪时明确显示加载状态，不用角色动画伪装完成；动画不能成为开始游戏的强制等待条件。

所有原有设置和词册行为保留：打开设置不重抽单词，开始使用已经预览的本局词册；搜索输入时隔离游戏快捷键。音乐、音效独立滑条在设置内可访问。

## 声音

继续使用裁去前 5 秒的 Red Rock Riviera，默认背景音乐 75%，动作音效默认 85%，保留用户主动调整的设置。菜单动效不修改 BGM 的播放位置、循环或音量。

若增加声音，只给“钩索收回”和“水滴落下”各一个轻声点，不让流水持续覆盖音乐。音效必须服从现有音效通道和静音设置；不恢复钟鼓，不增加角色语音。首版可先不加入新的菜单采样，视觉事件链必须能够独立成立。

## 素材拆分与 XBuilder 实现边界

现有 PNG 已把人物、倒影和菜单绘制在同一张图中，不能仅叠加一张会动的人物，否则会出现双人或残影。接入前需要：

1. 无 UI、无主角和绳线的完整背景底图，补齐被人物遮挡的台阶及水面。
2. 保持现有身份与视角的透明主角姿态：基础半跪、收索、抬头、调整护腕、起身。独立衣料层只在确有收益时拆分。
3. 水面反光遮罩、低分辨率水光层、涟漪 / 水滴小贴图，以及最多两层薄雾。
4. 独立标志与真实控件；正式文字由 UI 渲染，不保留概念图中的文字位图。

采用单独菜单状态管理人物与事件，不运行战斗角色物理、敌人 AI 或战斗特效。建筑与镜头不动，动作使用独立时间轴；离开菜单后停用这些更新。状态 / 造型未变化时跳过属性写入。

初版资源预算建议：主角按实际小尺寸与高分屏需求出图，单帧上限先以 256×256、最多 32 帧评估，RGBA 原始像素约 8 MiB；纹理、引擎对象和临时内存另算。复用持帧和基础姿态，避免多张全屏动画帧。镜面建筑使用预绘制倒影与局部覆盖层，不逐帧重新渲染整个世界。

初版活动装饰目标上限：两层雾、两组涟漪、4–6 个浮尘；先实现角色 / 绳索 / 涟漪的因果关系，再考虑远窗灯光。以上是预算和实现方向，尚未验证新菜单的实际帧率。

## 降级、暂停与可访问性

- 低性能模式保留基础衣料和一次收索循环，关闭浮尘、额外水光和远窗事件；不要通过降低 UI 响应速度省性能。
- 低动态偏好保留静态构图，关闭非必要动画和出发过渡；所有操作仍可直接完成。
- 网页隐藏时停更菜单时间，恢复时不把后台经过的几十秒累加成瞬时大位移。原生包能否可靠取得宿主可见性事件需接入时验证；最低要求是限制恢复时的动画时间步长，不能假定平台支持未核实的 API。
- 打开词册时不触发新的大动作，关闭后恢复自然待机；暂停、结算返回不带入战斗震屏、音效或物理残留。

## 验收

1. 原构图尺度保留：人物小而可识别、建筑宏大，角色活动不被右侧控件遮挡。
2. 正常窗口与高分屏观察 45–60 秒，至少可辨认两种主行为；身体接触点稳定，绳端与水滴位置连续，没有硬切、穿模或循环接缝。
3. 任意主行为期间开始、切换设置或打开词册都立即响应，单词不误换、按键不泄漏；反复切入切出不累加对象、事件或声音。
4. 镜头连续帧与 UI 坐标保持稳定。旧菜单“整张截图零差异”检查必须改为只检查静态建筑 / 标志 / UI 区域，并排除角色、雾和水面掩码，避免把正常动画当作抖动。
5. 同设备、同窗口分别测静态待机、收索事件、设置 / 词册打开、切入关卡的帧间隔和内存峰值，并与 v0.15.9 比较。报告尾部慢帧，不仅报告平均帧率；预算不达标时先撤掉次要环境层。
6. 保留现有音频专项检查：75% 默认值、静音、暂停续播、循环、深层关卡与攻击后音乐连续性；菜单动作不得触发音乐重播。

优先制作范围：干净底图 + 半跪 / 收索 / 抬头三组角色动作 + 绳线与涟漪 + 两层薄雾 + 真正的菜单控件。微光、植物、浮尘及额外起身变化作为第二轮打磨，性能验收通过后再加。
