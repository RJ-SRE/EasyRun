# 环境与技术设计

基线：2026-10-24。以仓库锁文件及当前源码为准。

## 1. 分层与修改入口

| 层         | 源文件                                                                | 责任                                         |
| ---------- | --------------------------------------------------------------------- | -------------------------------------------- |
| 工具环境   | `.node-version`、`package.json`、`pnpm-lock.yaml`、`scripts/`         | 固定依赖、安装、构建、测试与导出             |
| 当前场景   | `prototypes/runlab/build-rupture.mjs`                                 | z-order、造型、重心注册、平台/机关与导出清单 |
| 世界状态   | `prototypes/runlab/spx/rupture/main.spx`                              | 本局状态、计时、机构、粒子预算与遥测         |
| 角色       | 同目录 `Hero.spx`                                                     | 输入、移动、碰撞、状态呈现与镜头             |
| 瞬态特效   | `Particle.spx`、`Pulse.spx`、`Flux.spx`、`Trail.spx`、`PoseBlend.spx` | 生命周期、透明度、移动、跨重试清理           |
| 美术源文件 | `prototypes/runlab/art/rupture-v2/`                                   | 原图、提示词与可追溯来源                     |
| 网页宿主   | `public/rupture.js`、`.css`、`.html`、`index.html`                    | 加载、HUD、按钮、声音、本机记录              |
| 本地服务   | `prototypes/runlab/server.mjs`                                        | 静态资源与已安装 spx 运行时，绑定 127.0.0.1  |
| 对照原型   | `build-games.mjs`、`public/legacy.html`、`app.js`、`style.css`        | 两款旧玩法的可运行对照                       |

spx 在浏览器内运行。网页通过受控日志协议接收 `@state`、`@event`，不直接决定游戏碰撞与胜负。图片清单中的二进制内容解码成 ArrayBuffer 再交给运行时。

## 2. 版本与启动

Node 24.22.1，pnpm 11.9.0，spx 3.3.0，Playwright 1.64.1。XBuilder 参考源码固定为 `e2a4c45dfa0574ac7700fad94d2d4a6da7da8083`；完整编辑器及其云服务不是当前试玩的启动依赖。

```sh
bash scripts/bootstrap.sh
bash scripts/with-env.sh pnpm game:build
bash scripts/with-env.sh pnpm game:dev
```

基础安装脚本下载项目本地 Node/包管理器并校验 Node 下载文件，使用锁文件安装依赖，安装 Playwright 浏览器。Linux 如缺系统库，可在本机具有安装权限的环境执行 `pnpm exec playwright install-deps chromium`。影片转码需另行安装 FFmpeg；构建游戏本身不依赖 FFmpeg。

`game:build` 依次导入九宫格动作、导入十二帧跑步、生成旧原型、生成当前场景及加载预览图。`game:dev` 默认端口 4177，支持 `RUNLAB_PORT`。`game:test` 自动启动独立随机端口服务并通过 `RUNLAB_URL` 传给测试，结束时关闭自己的服务，不终止用户正在试玩的服务。

## 3. 当前关键参数

| 项目               | 当前值/行为                                         |
| ------------------ | --------------------------------------------------- |
| 内部视口           | 960×540，目标 maxFPS 60                             |
| 关卡状态           | 0 就绪 / 1 运行 / 2 成功 / 3 失败 / 4 暂停          |
| 单帧模拟 dt 上限   | 0.04 秒；严重掉帧时模拟时间不保证等于墙钟时间       |
| 地面目标水平速度   | 向右 330、向左 -280 世界单位/秒                     |
| 地面/空中加速度    | 2100 / 850 世界单位/秒²                             |
| 普通跳跃/重力      | 初速度 640，重力 1650，最大下落速度 1000            |
| 宽限与输入缓存     | 离地 0.12 秒 / 提前按跳跃 0.14 秒                   |
| 释放动能           | 0.46 秒动力段；向前 1120/560，向上 760/730（vx/vy） |
| 动能容量、机关锁止 | 1 次；风机与升降各约 9 秒                           |
| 风机/升降夺取窗口  | 水平距离分别 <380 / <320，另检查垂直距离            |
| 平台碰撞           | 顶面越过检测，身体横向半宽 13；不等于通用刚体碰撞   |
| 危险风机           | 锁止前，角色中心与风机中心的圆形距离判定            |
| 跑步               | 12 帧，每移动约 14 单位推进一帧                     |
| 过渡               | 普通状态约 55ms，跑步相邻帧约 22ms                  |
| 镜头               | 指数平滑，有限前视、竖向跟随与事件震动              |
| 普通粒子           | 上限 100；其他克隆另占全局额度                      |
| 状态输出           | 约每 60ms；事件即时输出                             |

输入/碰撞和动画表现分开：落地回弹只影响显示位置，不延迟下一次输入。暂停应停止世界时间与特效寿命。每次重试递增 attempts，旧瞬态对象发现所属局次失效后销毁。

## 4. 生成边界

`projects/`、`public/*.json` 的游戏清单、拆帧目录和 `exports/*.xbp` 为可重建产物，不提交重复副本。只有原始图集、注册数据与生成器是修改入口。导出包使用清单列出的文件，避免把生成目录里的旧文件打入包。

```sh
bash scripts/with-env.sh pnpm game:package
```

Python 仅使用标准库打包；会检查 ZIP 完整性及关键入口文件。导出后在 `prototypes/runlab/exports/` 得到三个 `.xbp`。它们不包含网页的完整结算界面和本机记录系统。

## 5. 运行边界与待办

当前验证在本机 Chromium。没有证明 Safari/移动端性能、20 分钟稳定性、真实网络首启、完整编辑器往返保存和原生包发布。官方运行时文件较大，正式 Web 部署需单独配置压缩、缓存、COOP/COEP 与错误恢复。

小场景的引擎更新率、页面 rAF 间隔、录制视频的帧率是不同指标；不得互相替代。性能研究详见历史技术报告。

当前源码无需外部 AI 服务、麦克风或账户。用户成绩留在 localStorage 的 `runlab-rupture-v2`；测试使用独立上下文。开放源码和推送远程不自动公开一个可访问的游戏站点。
