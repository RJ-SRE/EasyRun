# 十五房场景对象预算

2026-10-25，开发分支 `feat/expedition-boss-v2`。本次修复解决实际技能无法生成的问题，不据此宣称完整远征已验收。

## 问题与原因

spx 3.3.0 的全局活跃克隆上限为 300，隐藏的克隆同样占用额度。旧构建一次性创建全部 94 个平台、70 个锚点、51 组敌人及其预警/裂印、机关和绳段，超过上限。引擎拒绝后续克隆时没有触发游戏错误；因此出现 `bowshot` 事件并不能证明箭矢已经生成。

本次复现中，完整蓄力弓发出了释放事件，但 `Arrow.onCloned` 没有执行、敌人没有受伤。此前仅检查房间状态或基础近战通关的结果，不能证明投射物和整关画面完整。

## 固定显示槽

全部地形、机关、敌人数据仍用于物理和任务逻辑。`Scene.spx` 每帧把镜头上下 700 单位内的数据分配到稳定显示槽；离开范围后释放槽位，进入范围后复用。现有绑定尽量保持，不在镜头移动时反复创建/销毁角色。

| 显示对象 | 克隆额度 |
| --- | ---: |
| 平台 | 18 |
| 锚点 | 14 |
| 敌人本体、预警、危险效果、裂印 | 12 × 4 |
| 壁龛 | 6 |
| 机关 | 12 |
| 热流 | 2 |
| 目录归途指引 | 4 |
| 回声、钩索、钟锁、Boss 刃线 | 3 + 24 + 28 + 8 |
| 合计 | **167** |

敌人换绑时清理姿势交叠，平台换绑时清理开门动画。重开与排练复用原显示槽；不把一次重开当成新增地图克隆。地图扩充必须通过容量检查，不能依赖隐藏全图对象。

## 攻击优先于装饰

所有临时装饰效果共用 `takeFX`：粒子先受 60 个在场效果的限制，刀弧、动作交叠等可使用更高优先级额度；在场景、装饰和投射物总占用达到 240 后不再新增装饰，为后续攻击留出 60 个引擎槽。弓箭与敌方飞刃不走装饰拒绝路径。

`@render` 是只读遥测，分别记录预期与实际启动的场景克隆、缺失的显示槽、临时效果、活跃投射物，以及箭/飞刃的请求数和实际出生数。它不会改变攻击、伤害、房间或存档状态。生产界面不显示这些实现细节。

## 已取得的证据

- 地图数据测试检查全高度扫描、移动平台全程范围，以及敌人上下 180 单位的运动余量，均未超出槽位。
- 场景专项 34 项通过：十五房下潜/返程镜头切换、全部 167 个显示克隆实际启动、超量装饰请求后的真实箭矢命中、连续弓输入、反复重开与排练。检查中没有缺失显示槽，箭矢请求数与实际出生数一致，结束后临时对象可回收。
- 四技能专项 17 项通过，包括满蓄挂印、裂印重斩、贯穿两敌、平台遮挡、动作取消、回血中断、五段大招和重开清理。
- 当前全量回归继续执行。专项镜头位置夹具不代表玩家正常走完全图；这份预算也不代表低端设备帧率或未来新增任意弹幕仍必然安全。
