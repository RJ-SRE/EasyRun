## 1. 产品定义

一款面向偏好成熟视觉与操作挑战的玩家的二维动作跑酷冒险。玩家穿过仍在运转的机械遗迹，**从环境夺取速度，再承担环境失衡的后果**。夺取不是单纯充能：风机停转会让供能桥失压；冻结升降机构会改变可用的落脚点。选择来源、时机、方向与落点构成核心决策。

开发代号沿用 EasyRun，当前游戏名为《裂隙 / RUPTURE》，核心机制沿用“盗速者”。这是方向验证，不以现有原型长度、自动化成绩或生成美术推断市场规模、留存率和付费意愿。

### 当前生效与已退出的要求

| 生效                                               | 不属于当前版本                     |
| -------------------------------------------------- | ---------------------------------- |
| 先把游戏做得好玩，强调跑酷手感、环境反馈与路线选择 | 英语教学、发音评分、语音控制       |
| 成熟、克制、有材质与尺度感的场景                   | 多年龄段教育课程与儿童主题         |
| 用 XBuilder / spx 验证短篇二维动作体验             | 开放式 AI 剧情与实时云端 NPC       |
| 本地键盘试玩、反复练习、即时重试                   | 登录、商城、支付、联网排行榜       |
| 原始素材、实现、测试与决策可追溯                   | 同时承诺移动、主机与各类原生包上线 |

早期英语学习、精灵与机器人、人类灭绝的设定属于旧方案。用户随后要求脱离此前思考、重新设计不含英语学习的跑酷；旧 PRD 保留在历史提交，不自动并入当前世界观。当前蒙面行者是原型使用的造型，最终角色身份与完整叙事尚未定稿。

## 2. 受众、使用场景与价值假设

主要验证对象：喜欢横版动作、短关卡重复练习、路线优化和氛围探索的成年玩家。优先场景是电脑、实体键盘、数分钟试玩；不是儿童课程或碎片化背单词工具。

希望玩家体验到三件事：

1. 看懂环境状态并产生行动意图，而不是只等障碍出现后按跳跃。
2. 奔跑、跳跃、夺取、冲刺、落地能形成连续动作；成功归因于自己的判断。
3. 再跑一次有具体理由：换一条路、拿到回声、减少停顿、改进释放时机。

商业价值是待验证假设：有辨识度的机制与美术可能支撑独立动作游戏。先验证理解、乐趣与主动重试，再讨论内容量、销售平台和定价。本阶段不实现付费功能，也不宣称已验证商业需求。

## 3. 核心循环

观察机械设施与地形 → 接近动能来源 → 夺取并观察环境变化 → 选择向前或向上释放 → 空中修正与寻找落点 → 收集可选目标或抵达出口 → 看时间/结果并重试。

- 动能容量为一次；空槽时按动作键尝试夺取，满槽时按同一键释放。
- 夺取不替玩家决定路线。风机锁止与桥梁失压相连，安全窗口有时间压力。
- 失败后立即允许重试，避免长等待。结果页只解释本局结果，不强迫填写反馈。
- 成绩衡量完成效率；可选收集提供另一种目标，不把每次行动都变成强制任务。

## 4. 已实现玩法规则

### 4.1 输入与动作

| 编号   | 需求           | 当前行为                                                       |
| ------ | -------------- | -------------------------------------------------------------- |
| MOV-01 | 即时左右移动   | A/D 或方向键；有加速、减速、空中操控                           |
| MOV-02 | 可控跳跃       | Space；普通跳跃松键可缩短高度，含输入缓存与离地宽限            |
| MOV-03 | 夺取与释放     | E 或 Shift；仅按下沿触发，不因长按每帧重复                     |
| MOV-04 | 选择释放方向   | 默认向前；W/上键与 E 配合可向上释放                            |
| MOV-05 | 快速重试与暂停 | R 重置；Esc 暂停/继续；Enter 开始或继续                        |
| MOV-06 | 连贯呈现       | 12 帧跑步、按位移驱动周期；起跳/下落/冲刺/着地短过渡与落地回弹 |

当前 W/上键也可触发跳跃；W+E 不是全套自由瞄准系统。冲刺释放目前朝关卡前进方向，不等于左右全方向冲刺。可变跳跃不用于提前截断动力冲刺。精确参数与碰撞规则见技术文档和源码。

### 4.2 场景机构

| 编号   | 机构     | 规则与反馈                                                        |
| ------ | -------- | ----------------------------------------------------------------- |
| MEC-01 | 风机     | 接近后可夺取；危险叶片立即失去伤害，视觉叶片逐渐刹停；锁止约 9 秒 |
| MEC-02 | 供能桥   | 首次夺取风机后失压；短暂振动/下沉后加速坠落，伴随火星与碎屑       |
| MEC-03 | 升降机构 | 可夺取并冻结约 9 秒；固定在当前高度，解除后从原相位继续运动       |
| MEC-04 | 上层回声 | 选择上层路线可回收一枚可选目标，回收后隐藏并加分                  |
| MEC-05 | 出口     | 越过终点触发通关、结算、重试与可选反馈                            |

风机与升降机构各提供一次锁止窗口；冷却期间不能反复刷取同一来源。第一桥梁破坏在当前局内不可逆，重试恢复。关卡当前是手工配置的短片段，没有程序生成或无尽模式。

### 4.3 胜负、分数与记录

- 风机危险区域碰撞、坠出场景或本局超过 90 秒会失败。
- 每次成功夺取 +150；上层回声 +500；通关时间奖励按剩余整秒计分，当前公式为 `int(90 - elapsed) * 10`。
- 当前没有已完成的连击计分体系；遥测中的旧兼容字段不代表产品功能。
- 本机保存最近 100 条成绩/反馈记录，支持导出 JSON；不需要账户，不上传玩家数据。
- 反馈为“再走一次 / 还缺点什么 / 没有感觉”，自选填写；自动化结果不能混作真人反馈。

## 5. 场景与关卡设计

当前内部视口为 960×540，横向推进。远处是巨大机械建筑与风暴雾海，近处为可辨识的平台、风机、升降井和出口灯火。橙铜色提示旧工业材质，冷绿光提示动能，背景细节不应遮蔽落点。

| 区域       | 玩法作用                     | 当前实现                     | 后续需验证                   |
| ---------- | ---------------------------- | ---------------------------- | ---------------------------- |
| 风机墓场   | 学会夺取，理解环境代价       | 风机、供能桥与第一段动力穿越 | 首次玩家是否在失败前理解因果 |
| 悬空升降井 | 用冻结高度和释放方向选择路线 | 下层快线、上层回声、多个落点 | 两条路是否都清楚且值得尝试   |
| 最后的灯火 | 收束一次行动并给出结果       | 出口、时间与可选反馈         | 结算能否促使有目的的重试     |

熟练自动化路线约 6–7 秒，仅证明这段片段可完成。下一阶段目标是一段 60–90 秒的有代表性手工关卡，不把现有地面简单拉长；应加入“安全认识机制—变化练习—组合挑战—可选风险—收束”的节奏。

## 6. 美术、动画与声音要求

### 已有表现

原始环境与角色图集采用成熟的暗色工业幻想美术。角色不是几何小人；场景有视差、漂移雾与连续雨幕。夺取有弧线能量流；冲刺有逐渐消散的残影与光丝；脚步/落地有水滴、涟漪和雾气；桥梁破坏有碎屑。

角色造型统一重心与脚底基准，奔跑按移动距离播放，镜头按时间平滑跟随。落地呈现使用弹簧回弹，不锁死输入。声音默认关闭，开启后提供脚步、冲刺气流和机械冲击等合成反馈。

### 质量门槛

- 主要动作应在正常速度下连续、可读，不能以静态截图代替动作验收。
- 场景美术应帮助分辨可站立面、危险区域、动能来源和出口。
- 特效的起点、方向与发生事件一致；暂停冻结、重试清理，不遗留上一局效果。
- 雨幕循环不产生整屏跳变，镜头避免瞬间追到目标位置。
- 生成的跑步素材仍有衣摆、关节与前后腿一致性问题，须进一步精修；目前不是完整骨骼动画或专业动画终版。
- 降低镜头震动、音量分级、自定义按键等可访问性选项尚未实现，进入公开试玩前评估优先级。

## 7. 页面与用户流程

加载提示 → 开始页与操作说明 → 游戏/HUD → 暂停或结果 → 重试。加载失败显示错误，避免无响应空白页。HUD 显示时间、分数、区域、动能与机构状态；页面可全屏，失去可见性时暂停。

触屏与手柄目前不在已验证范围。手机访问提示使用电脑和实体键盘。当前服务绑定本机地址，推送源码到 GitHub 不等于部署了在线试玩站点。

## 8. 技术与非功能边界

- 核心移动、碰撞、机构、计时和世界特效在 spx 内运行；网页负责界面、音频和本机存储。
- 自定义控制器使用顶面越过检测；尚不能据此承诺任意斜坡、墙体和复杂连续碰撞。
- 普通粒子上限 100；其它瞬态精灵也消耗运行时全局克隆额度，需要保留余量。
- 当前目标为桌面流畅体验；已有测量是本机浏览器短时录制与简单引擎探针，不能替代不同硬件、长时间运行、真实网络首启的性能验收。
- `.xbp` 可构建且 ZIP 结构已检查；完整 XBuilder 编辑器重新导入/保存/导出仍待验证，尤其视口尺寸。
- 项目固定 Node、pnpm、spx 和锁文件；源码与资产可以从干净检出重建。工具安装包和下载缓存不入 Git。

## 10. 版本推进与停止条件

本次 v0.3 以“当前片段可复现、过程可追溯”为交付。下一阶段先处理动作一致性和落点可读性，再扩展一段关卡，随后开展小样本试玩。若玩家仍无法理解夺取后的环境变化、主要靠提示背操作，先调整机制表达；若用户只重试一次但没有明确目标，先改路线与挑战，不以增加账号、AI 或付费系统补救。

三天两夜仅作为早期资源约束保留。后续采用相对工作日规划，不把历史预算当成今天重新承诺的截止时间；具体任务与验收见路线文档。
