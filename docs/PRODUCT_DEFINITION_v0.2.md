# 产品定义 v0.2：用英语完成冒险

日期：2026-10-23。这是产品定位文档的修订号，不是已发布游戏版本。游戏主体尚未开发。

已确认的方向：用户选择“先是好玩的冒险游戏，英语帮助完成任务”。首批仍面向成人英语初学者，暂不考虑付费功能。下文的信使身份、剧情和关卡节奏是据此整理的具体设计方案，工作名称仍沿用“词境跑者 WordRunner”；GitHub 仓库名为 EasyRun。

## 1. 一句话定义

**一款面向成人英语初学者的氛围型动作冒险跑酷游戏：玩家扮演旅行信使，穿过有挑战的路线，通过理解英语线索、使用简短英语指令完成投递。**

玩家进入游戏的直接目标是完成一次冒险。动作手感、世界氛围、任务进展与克服障碍带来游玩动力；英语承载场景信息和行动意图。教学支持出现在需要帮助的时候，学习记录用于了解发生了什么，不代替冒险本身。

暂定对外介绍：**“穿过雨夜与云海，用你的声音完成下一次投递。”**这是一条表达方向，不宣称任意自由英语都能被理解。

## 2. 目标玩家与体验承诺

优先招募有轻度动作或冒险游戏兴趣、能接触简单英语但不习惯开口的成年人。他们可以英语基础弱，但不必接受幼儿化角色或界面；也可以喜欢明亮自然场景，不需要固定选择暗色都市。

希望玩家产生三个可观察的反应：

1. **“我想把这次任务完成。”**清楚目的地、障碍和进展，失败后知道怎样改进。
2. **“这句英语刚好帮我解决了问题。”**表达含义与动作或场景有关，反馈立即可见。
3. **“下一次我可以自己说出来。”**同类情境再次出现时，帮助减少，但随时可以求助。

这些是设计目标，尚无本产品试玩数据证明已经实现。首版不承诺系统课程覆盖、口语流利度或专业发音评价。

## 3. 产品优先级

| 层次 | 玩家获得什么 | 设计取舍 |
| --- | --- | --- |
| 第一层：冒险与动作 | 氛围、速度变化、路线推进、完成任务的满足 | 先保证按键操作、碰撞和关卡节奏，再接入语言互动；语音仍是完整交付的必需项 |
| 第二层：英语作为工具 | 看懂路标和无线电线索，用英语表达行动意图 | 目标表达决定任务设计，避免任何句子都能换金币或能量 |
| 第三层：按需帮助与回顾 | 示范、释义、提示、表达重现和真实记录 | 不要求先完成一页练习才能开跑；回顾不阻挡重玩或离开 |

基础动作是否好玩可以先用按键灰盒检查，但最终 P0 必须包含真实语音、任务反馈和异常恢复；“游戏优先”不撤销用户的英语教学与声控需求。

## 4. 玩家身份与世界

**身份：旅行信使。目标：把一份讯息送到接收站。**

同一位正常比例的旅行者，在两种视觉主题中完成投递：雨夜都市有站台、屋顶和信号区；云海遗迹有石桥、石拱门和观测塔。两主题共用关卡与动作结构，避免三天内建设两套剧情系统。

叙事采用三处轻量表达：开局一句投递目标，途中一处与任务有关的环境变化，终点一句回执。首版不增加长过场、多结局、任务树或开放地图。

关卡推进依赖行进距离和状态。剧情可营造紧迫感，但语音等待不能消耗一个暗中的全局倒计时，让玩家因识别延迟丢掉任务。

## 5. 核心循环

**接到投递 → 观察路线 → 跑、跳、滑行与变速 → 在关键位置理解线索或开口表达 → 世界回应 → 抵达目的地 → 自由选择重玩或回顾。**

玩家想继续的原因应来自更好的动作表现、对场景的兴趣和任务进展。首版优先用已有路线的表现改善验证复玩，不提前许诺未制作的分支路线或下一章。

普通路段保持连续动作。语言互动集中在少量视野清楚、可预判的关键位置；一局约 3 次重点互动，每次只提出一个意图。六动作仍都能语音触发，不要求玩家对每一次跳跃喊口令。

## 6. 英语怎样进入玩法

| 场景 | 英语提供的作用 | 玩家行为与反馈 | 首版实现范围 |
| --- | --- | --- | --- |
| 屋顶低门 / 石拱低门 | 提示低处通行，练习 under 与滑行动作 | 在安全起点说 Slide 或 Slide under the gate，角色通过低门 | 复用 Slide；不同难度的提示与允许表达由任务表决定 |
| 信号区 | 无线电提示 The signal is red. Wait here. | 玩家 Stop / Wait here，在安全位置等待；通行时恢复 Run | 停止与机关周期沿用 PRD；背景语音不进入玩家指令识别 |
| 宽阔通道 | 情境提示需要提速，表达 Sprint / Run faster | 角色明显前倾并冲刺，体力和速度反馈可见 | 使用现有速度与体力系统；不把长句直接交给自由对话模型 |

听懂线索后按键操作可以记录为听力任务结果；主动说出允许表达可记录为口语任务结果。两者分开。玩家能凭画面猜对动作时，不能只凭通关就宣称理解了英语。

后续可考虑与固定场景角色进行简单请求，例如 Open the gate, please，但它仍属于后续明确范围的交互，不因写进定位就升级为三天 P0。

### 主动开口与按键如何共存

- 主线始终可用按键完成，麦克风故障不成为付费或通关门槛。
- 语音任务在安全位置提供表达时间，动作执行的起点与时机保持明确。
- 英语帮助玩家理解世界和表达行动，不靠“按键更弱、声控更强”强迫使用语音。
- 示范、中文释义和动作图示可按英语档位提供；独立任务不能提前显示正确口令。
- 同一个动作的碰撞、速度和冷却不因输入方式改变；按键通关不生成口语完成记录。

## 7. 第一局：夜行急件

以下是 90 秒有效行进时间的体验草案；初次操作说明、语言帮助和等待会增加实际时长。

| 参考段落 | 玩家体验 | 重点 |
| --- | --- | --- |
| 0–15 秒 | 看见远方接收站，得到一句目标，跑起来并跨过低障碍 | 尽快获得操作与前进的感觉；无需先背词 |
| 15–35 秒 | 来到低门，看到清楚的通过方式，尝试 Slide 或短句 | 第一次英语互动立即带来有意义的动作 |
| 35–55 秒 | 信号变化，判断何时停、何时继续 | 动作挑战包含观察与节奏，不能只有加速 |
| 55–75 秒 | 宽阔通道冲刺，随后慢跑恢复体力 | 速度与资源选择；语音为可用输入，不强制重复朗读 |
| 75–90 秒 | 将已有动作组合起来，抵达投递点 | 完成一个完整小故事，不临时增加新技能 |

章节结算先展示投递结果和真实游戏表现，明确提供“再跑一次”。英语回顾作为可展开区域，展示本局独立使用和需要帮助的表达，不默认变成考试成绩单。

## 8. 第一版保留与暂不加入的内容

| 保留的交付要求 | 本次调整的呈现 | 暂不加入 |
| --- | --- | --- |
| 两主题、六动作、真实语音与按键、独立英语和动作难度 | 先冒险目标、再在场景中获得语言帮助 | 开放世界、任务树、多结局 |
| 18 条任务卡、示范和提示、下局复习、结算记录 | 任务卡作为编排数据，每局只用少量重点表达 | 新动作体系、多个 NPC、实时自由对话 |
| 技术错误容错、语音安全区、暂停与重开 | 表达后以角色和环境响应为主要反馈 | 词汇考试门槛、发音排行榜、强制打卡 |
| 成人友好美术，明暗主题都能选择 | 学习回顾不阻挡继续冒险 | 支付、订阅、付费墙和定价实验 |

三天范围仍是一条关卡、两套主题，不承诺增加章节数量。18 条任务卡保留为三英语档位的内容池，一局围绕约 3 次重点互动组织，不把 18 条全部塞入首局。

## 9. 怎样验证这个定义

验证顺序调整为 **游戏吸引力 → 英语互动是否自然 → 去提示后能否使用**，三项分别记录。

1. 观察玩家能否说清这局的任务、是否愿意把投递完成、失败后是否主动尝试改进。
2. 在没有额外奖励和研究者催促时，观察是否选择再玩。先记录行为，再问最想继续或最想跳过的部分。
3. 观察语言互动前后是否频繁中断节奏；确认是任务难度、表达耗时还是技术故障造成。
4. 在可以按键接管时，观察是否仍主动选择语音。若只靠强制开麦维持使用，说明语音价值未验证。
5. 对原来不会的表达做次日新情境检查。游戏好玩与学会英语不能互相代替，也不能由 ASR 分数代替。

首轮成人试点的时间窗、样本限制和指标定义继续使用 [产品路线](PRODUCT_ROADMAP_v0.1.md)，补充记录玩家继续或退出的具体原因。这些检查尚未执行。

## 10. 对已有规划的影响

- PRD：开局从先学少量表达调整为先接任务，在场景需要时提供示范；核心技术与 P0 数量不变。
- 路线：后续“练习内容版”调整为“冒险章节版”，章节有自己的目标与动作节奏，表达随任务安排和复现。
- Backlog：先检查灰盒动作手感，再检查语言任务对节奏的影响；游戏结算与可展开语言回顾共同保留。
- 美术：旅行信使、雨夜都市、云海遗迹继续采用，不重新启动一轮无范围的美术扩张。
- 工程：本次只更新定义与文档，不代表游戏代码、真实识别或新交互已实现。
