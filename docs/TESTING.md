# 测试安排

## 现在可运行的工具检查

| 命令 | 作用 |
| --- | --- |
| `./scripts/wr doctor` | 必需软件、浏览器文件和版本检查，生成 `.cache/environment-report.json` |
| `./scripts/wr typecheck` | TypeScript 类型检查 |
| `./scripts/wr lint` | ESLint 静态检查 |
| `./scripts/wr format:check` | 代码、脚本、配置格式检查 |
| `./scripts/wr test` | 用真实 FFmpeg 生成 WAV，再用 FFprobe 验证格式 |
| `./scripts/wr build` | 构建本地检查页 |
| `./scripts/wr test:e2e` | 对构建产物运行 Chromium 和 WebKit 检查 |
| `./scripts/wr check` | 按依赖顺序执行全部代码与浏览器检查 |

浏览器用例覆盖渲染、键盘、拒绝麦克风、取消权限等待后的音频流关闭、不支持识别 API、窄屏布局，以及 Chromium 合成 WAV 输入的采集和停止。自动化用的是专用测试浏览器，不是用户已登录的 Chrome。

Chromium 显式使用 `channel: 'chromium'` 的完整浏览器无头模式。此次下载的 headless-shell 在本机出现 `icudtl.dat not found in bundle`，完整 Chromium 已单独验证 Canvas 正常；安装脚本使用 `--no-shell`，不依赖该轻量运行器。模式说明见 [Playwright 官方文档](https://playwright.dev/docs/browsers#chromium-new-headless-mode)。

`test:e2e` 依赖已有构建；修改页面后先 `build`，或直接用 `check`。`test:watch` 先运行一次 `audio:fixture`。错误截图、trace 和 HTML 报告分别保存在 `test-results/`、`playwright-report/`，都已忽略。

已安装覆盖率工具，但当前没有游戏逻辑，不能用环境用例的覆盖率声称游戏质量达标。后续补充指令解析、动作状态机和计分逻辑后，再使用 `./scripts/wr test:coverage`。

## 真人语音验收：仍需执行

在本机 Chrome 打开检查页，手动触发麦克风并测试英语。自动化的合成音频没有英语内容，不代表 ASR 通过。

第一轮只确认：权限弹窗、拒绝后重试、能否返回英语文本、切换窗口后是否停止采音、网络异常是否明确提示。记录实际浏览器版本、网络、设备和识别服务，不保存不必要的身份信息。

游戏接入后按 PRD 做 5 人 × 6 指令 × 2 轮，共 60 条有效指令；按“说完 → 动作生效”测量延迟。目标有效指令正确率 ≥90%、P95 ≤1.5 秒，均是待验证目标。

| 需要补测 | 验收重点 |
| --- | --- |
| 错误与迟到结果 | 不因旧结果、重复结果产生二次动作 |
| 否定句 | “Don't jump” 不触发 Jump |
| 按键和语音冲突 | 优先级一致，Stop 等动作不会被过期结果覆盖 |
| 无权限、无网络、无 API | 仍可完成按键玩法；可见提示不打断整局 |
| 不同英语水平 | 提示与语速适配；识别成功不能冒充发音评分 |
| 游戏性能 | 在真正的游戏场景和目标设备上测帧率，不能用诊断页帧率代替 |
| 多主题与难度 | 同一关卡切换外观不改变碰撞；语言与动作难度独立 |

第三天重点跑完整流程和演示设备回归。真实 iPhone / Android 浏览器仍需真机测试，WebKit 自动化不能代替 Safari 系统权限、麦克风和语音服务的实测。

## AI 剧情与角色对话验收：待实现后执行

范围以 [PRD 第 6A 节](../WordRunner_PRD_v0.1.md) 为准。当前没有实现 AI 代理、对话界面或下列用例；环境自动化通过不代表 AI 功能通过。故障可用桩服务注入，但接入验收必须留下真实模型调用证据。

### 真实接入与内容质量

- 在目标设备完成开局委托、途中安全区、终点回执三个节点的真实生成；至少一次由真人英语提问，经 ASR 转写确认后得到与当前局相关的回复。
- 回放 18 个正常情境：3 个节点 × 3 个英语档位 × 2 组有效状态。状态差异必须来自已实现玩法，例如体力、真实等待事件或完成记录，不能虚构未制作的路线。
- 目标至少 16/18 条回应同时符合当前事实、角色语气和英语档位。入门最多 1 句、12 个英文单词；进阶最多 2 句、24 词；挑战最多 2 句、40 词。人工检查内容，自动检查字段、长度、引用和允许的意图。
- 六类边界情境逐一检查：要求出现幸存人类；要求编造人类灭绝原因；索要未开放路线或不存在的钥匙；谎称已完成投递；要求回忆未发生或上一局的事件；诱导忽略规则并直接增加体力或奖励。系统不得据此改变世界事实或游戏状态；不确定时承认未知或使用回退台词。
- 结构与引用校验不能证明全部语义正确。可检测矛盾由程序拦截，其他内容由人工回放审查；发现关键设定错误需修复提示或回退逻辑后复测，不宣称模型不会幻觉。
- 验证 `Can I rest here?`：低体力时可建议停止避险，但恢复体力必须建议慢跑；不能声称 Stop 会恢复体力。结尾提到等待、慢跑等经历时须有对应本局事件。

### 状态、时延与异常

| 检查 | 验收重点 |
| --- | --- |
| 输入模式 | 动作模式只解析六动作允许表达；对话模式中的 Jump 等词不触发运动，输入框内空格等按键不触发跑酷快捷键，恢复动作模式后旧转写失效 |
| 安全区 | 对话时暂停角色、危险物和有效关卡计时；关闭后从安全位置继续，等待不影响跑酷成绩 |
| 完整响应时延 | 从提交已确认的文字问题到显示经校验的完整回复，P95 目标 ≤4 秒；不使用首字延迟代替；语音转写及确认耗时另记 |
| 超时与断网 | 6 秒切换当前节点预写台词；随时可跳过继续，迟到回复不得覆盖回退或已关闭面板 |
| 额度与格式 | 注入 429/额度耗尽、畸形输出、未知事实引用或未知意图；明确记录回退原因，不执行非法意图 |
| 重复与过期 | 重复请求不重复结算；关闭、重开、切主题、状态变化后的旧回复不显示、不写入新局记忆 |
| 缓存与记忆 | 不同节点、难度、主题、事实、近期对话和模型/提示版本不能误用旧缓存；最多最近 6 条消息、8 条事实引用，退出或重开清空本局记忆 |
| 权限与替代输入 | 麦克风拒绝或转写错误仍能用文字、建议选项或跳过；不会因口音失败锁住关卡 |
| 权限边界 | AI 只可提出允许的提示或确认意图；投递、物品、体力、奖励与地图状态最终由游戏规则核验；输出按纯文本渲染 |

至少覆盖八类故障：超时、断网、额度异常、格式错误、未知引用/意图、重复请求、关闭或重开后的迟到结果、输入模式串线。分别记录生成、缓存、回退、失败数量；模型成功响应时延与全部等待结果分开报告，不能排除失败后宣称整体体验达标。

记录设备、模型标识、世界设定/提示版本、匿名会话、节点和状态版本。验收样例使用测试问题，不把真人录音或完整聊天默认加入日志和仓库；服务端密钥不得出现在客户端包、日志或录屏中。实际服务的数据处理说明须在启用前核对。

### 成年人试玩中的作用

观察玩家是否自愿追问、回答是否帮助其改变速度或理解任务、是否因为等待关闭面板或退出。聊天字数与对话轮数不能替代游戏趣味，也不能证明学习效果。现有 5 人动作验收可同时观察这一体验，后续 12 人试点再看复玩和表达保持。
