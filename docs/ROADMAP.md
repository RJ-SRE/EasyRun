# EasyRun 产品路线 · 从单机猎战到双人协作

更新：2026-10-25。当前基线为 `main` 的 v0.10 猎战重构；当前行为以 [PRD](PRD.md) 与 [猎战设计](HUNT_V10.md) 为准。

**本文为规划，不是功能交付说明。此次仅整理文档，没有实现联机、更多章节、回放、云存档或支付。** 各阶段按验证结果推进，不承诺版本日期。

## 1. 已有基础与不再沿用的方案

| 已实现       | 当前范围                                                                  |
| ------------ | ------------------------------------------------------------------------- |
| 单机完整冒险 | 五区十五段、三场精英、三形态守心者、夺心后黑潮返程、检查点与两档战斗难度  |
| 移动与战斗   | 钩索、跳跃、蹬墙、方向冲刺、地空连段、四技能、八类敌人及九种排练          |
| 可选铭文     | 每局随机 30 词、预览、拼写 / 辨义、每次技能答题、失败取消、无技能时间冷却 |
| 表现与记录   | 独立慢速表现、五区美术、猎手手记、18 项成就、本机战绩 / 词册 / 成就导出   |
| 工程交付     | 可重建源码与资产、自动验证、Git 历史、来源与证据记录                      |

机关修复、护送、档案底座、外置钟锁与语义机关不再作为后续主线。旧 [十五房机关远征方案](planning/thirty-word-expedition/README.md) 仅用于追溯，不能重新标为待实施。角色配音与 AI 对话不自动恢复。

当前十五段是一个完整关卡，尚不是多个独立章节。在线排行榜、通用存档导入、手柄、联机、账号和支付都未实现；独立五通道原型尚未接入主关卡。

## 2. 产品判断原则

1. **动作体验能独立成立。** 先用纯动作模式验证移动、战斗与返程；铭文需要带来主动使用意愿。
2. **新内容带来新选择。** 不用更高血量、更长空路或更密的题目替代玩法。
3. **保持当前明确约定。** 单机四技能每次独立答题，答错取消，无免题续招、无技能时间冷却；不为了联机便利偷偷改变。
4. **学习成果与游戏成果分开。** 通关、答对、提示使用、实际命中与延迟记忆不是同一指标。
5. **先验证风险最大的最小片段。** 联机先做双机战斗可行性，章节先做一个高质量遭遇，不同时启动大规模内容生产。

## 3. P0：理解、手感与稳定性

优先开展 5–8 名目标成年玩家的探索性试玩，包含动作熟练度和英语水平不同的玩家。纯动作与铭文体验交换先后顺序，记录顺序影响；该规模仅用于发现问题，不估计市场份额或学习效果。

| 问题                 | 观察方法                                     | 后续决策                                           |
| -------------------- | -------------------------------------------- | -------------------------------------------------- |
| 钩索与落点是否易懂   | 首次按住 / 松开、求助点、失败位置与玩家解释  | 调整引导、目标高亮、镜头前视                       |
| 敌人是否公平         | 让玩家说出被谁、为何命中；观察前摇和收势识别 | 调整轮廓、预警、攻击间隔和组合                     |
| 是否自愿使用多种攻击 | 记录真实命中与打法切换，不仅统计按键次数     | 修正某招无用或一招压制全部敌人的问题               |
| 铭文是否切断行动     | 观察忘记落点、回避技能、连续出题时的退出意愿 | 优化题面、输入交接和遭遇动机，不通过免题或冷却掩盖 |
| 是否愿意重试         | 观察自发再开、退出节点、想尝试的路线和原话   | 决定扩展内容还是先改主循环                         |

配套待办：

- 主角与敌人关键姿态、衣摆、受击与落地衔接精修；复核强效果下的攻击可读性。
- 自定义键位和左手 / 右手布局，检查作答输入与战斗键冲突；完善已有减少运动偏好的覆盖范围。
- 对目标设备检查首启加载、资源占用、输入到反馈、20 分钟连续运行与反复重开；分别记录环境和提交。
- 独立审校当前 82 词的词性、目标义项、语境和干扰项；必要时更新内容版本与迁移。
- 复核干净安装、CI、浏览器支持和编辑器往返；自动化与人工体验分别验收。

**进入下一阶段的条件**：关键操作不再依赖现场解释，主要受击原因可辨认，出现自发重试和打法变化，并且已定位铭文最明显的中断问题。若仍是“卡住、看不懂、只按 J”，先修体验。

## 4. P1：让重玩产生新的战术

| 提案           | 最小可玩设计                                                               | 验收重点                                                       |
| -------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 猎战委托       | 少量手工验证的遭遇模板，使用可复现种子选择组合、目标与起点；可分享同一挑战 | 种子对应明确内容版本；所有组合可达、可读，不随机出无解围攻     |
| 目标猎杀与撤离 | 一段短路线里锁定目标敌人；其余敌人可绕行，击杀后有新的撤离压力             | 选择来自路线和优先级，不重新加入按钮、护送与机械任务           |
| Boss 挑战      | 单独挑战守心者或精英，战后查看受击来源与尝试次数                           | 方便练习，不把排练数据冒充完整冒险成就                         |
| 个人回放与幽影 | 先记录本机位置、动作事件和关键节点，回看自己的路线                         | 标明版本；不假设输入重放必然确定性一致，不把幽影当真实碰撞角色 |
| 技艺挑战       | 空中接力、少受伤、破架后追击等可选目标                                     | 奖励称号和表现；不卖数值，不逼玩家重复无趣动作                 |

先验证一个短遭遇能让玩家采取至少两种合理策略，再扩展模板。挑战的变化应能解释为“这次先处理谁、从哪里进入”，不能只说“这次敌人多了一些”。

涉及新成绩规则时区分战斗难度、铭文开关、词汇难度和内容版本；当前本机记录不具备公开竞技可信度。每日委托、在线榜单和自动回放分享均需额外开发。

## 5. P2：局域网双人纯动作合作

### 想带来的体验

两位玩家进入同一座旧城，独立移动和瞄准，共同处理不同职责的敌人。一人吸引裂甲卫朝向，另一人绕背或处理缝魂师；面对双生猎手时分开牵制；夺心后共同逃离黑潮。

合作的价值应来自分工、支援和路线沟通，不只是在屏幕上多放一个主角。镜头保持独立，通过队友方向 / 高度提示和有限标记协作；房间过渡在明确的安全点会合，避免玩家被强制拉回或全程互相等候。

### 首版候选范围（全部未实现）

| 内容 | 首版规划                                                                       | 暂不包含                                 |
| ---- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| 房间 | 一人创建本地房间，另一人通过局域网地址与加入凭据进入；显示版本、难度、准备状态 | 互联网匹配、自动跨网穿透、四人房间       |
| 对局 | 两名玩家、纯动作、固定验证切片，之后再扩展完整下潜 / 返程                      | PvP、玩家交易、联机铭文                  |
| 合作 | 独立镜头、共享敌人与精英目标、队友方位标记                                     | 分屏、复杂职业树、永久装备成长           |
| 救援 | 倒地进入有限救援窗口，救援有动作承诺；共同失败回到团队检查点                   | 无限倒地拖时间、复活付费、单人无限拖队友 |
| 结算 | 先看团队目标，再展示伤害、救援、破架与支援贡献，减少抢尾刀                     | 将个人输出作为唯一胜负依据               |
| 恢复 | 客机短断线进入明确团队等待，重连取得权威快照；超时退回检查点或结束房间         | 首版主机迁移、断线期间客户端自行结算胜利 |

救援时限、会合宽容度、双人血量 / 攻击预算都需实测。不能简单把敌人数和生命翻倍，否则可能同时破坏节奏与对象预算。

### 技术可行性先行

当前角色、输入、伤害与存档以单人为中心，宿主只是静态服务；不是增加 WebSocket 就能变成双人游戏。

建议先评估 **Node 局域网房间服务 + 主机浏览器权威 spx 模拟 + 客机输入与表现同步**。房间服务处理连接和消息，主机负责实体位置、敌人 AI、伤害、死亡和关卡状态；客机发送带序号的输入，接收状态。这个方案仍需验证运行时桥接能力，不宣称已有无界面 spx 服务器。

按以下顺序拆解：

1. **双角色本机模拟**：把单人状态拆为玩家 ID、独立生命、输入、技能、碰撞与动画；先在同一模拟中验证两个角色。
2. **最小网络切片**：一座平台、一种敌人、两台电脑；验证输入确认、快照、实际命中归属与死亡一致性。
3. **镜头与显示预算**：两位玩家可相距较远，当前围绕单一镜头复用显示槽的方案需要重审；记录每端可见敌人与投射物，不直接复用 121 克隆结论。
4. **延迟表现**：先做快照插值和纠偏，再决定是否加入本地预测。以实测选择同步频率，不预先承诺低延迟手感。
5. **掉线与局次**：房间 ID、玩家 ID、内容版本、局次、消息序号防止旧输入重复执行；重连恢复当前状态，主机离开时明确结束房间。
6. **局域网运行环境**：验证远程地址访问时 WASM 所需的安全上下文和 COOP / COEP；必要时提供受信任的 HTTPS 方案。不能把 localhost 可用当作局域网已经可用。

`0.0.0.0` 监听只解决访问入口；同网地址不等于同一世界。现有 `latestState` 等观察字段用于调试，不能不经设计就变成稳定网络协议。

### 联机验收门槛

- 两台实际设备可建房、加入、开始、共同击杀并完成撤离；角色、敌人生命、关卡与结果一致。
- 测试输入重复、乱序、延迟、连接中断、页面后台、主机退出、版本不一致与重新加入；不会重复伤害或复制奖励。
- 观察约 0 / 50 / 100 / 150 毫秒注入延迟下的误差与手感，作为测试档位，不作为目前支持承诺。
- 进行至少 20 分钟的双机连续游玩，记录双方帧时间、同步误差、资源峰值和异常。
- 玩家能描述并实际完成分工；如果双方始终各打各的，先改遭遇，不急着扩成四人。

这一阶段工程成本最高，需单独的可行性结论与开发计划；可以在一个房间验证失败后停止扩展，而不是为了“有联机”迁就所有规则。

## 6. P3：铭文多人、异步挑战与长期内容

### 多人铭文是独立设计问题

单机答题冻结整个战斗。如果任何玩家每次施法都让全队冻结，会产生抢控制权和连续暂停；若只冻结答题者，其他人的攻击与敌人的威胁又继续，容易形成免费保护或不公平惩罚。

因此同步双人首版只支持纯动作。后续比较团队共同聚焦、各自承担风险的个人聚焦等实验时，必须明确受伤、时间、敌人 AI、输入与成绩如何处理；在验证前不承诺采用任何一种。不通过增加单机技能冷却、免题释放或降低另一人的答题要求解决。

较早可探索 **异步同种子挑战**：玩家在自己的世界作答，比较各自路线和完成结果。动作时间、真实耗时和作答表现分别展示，同难度 / 同铭文规则比较，不混成一个有误导性的总排名。这仍需挑战版本、种子与数据校验的开发。

### 其他候选扩展

- **新章节**：保留垂直空间特色，先探索不同高度组织、光线与敌人生态；完成一个内容切片再量产地图。
- **个人词库与复习**：在审校与版本迁移完善后，考虑限定格式的自定义词组和延迟复习任务；不默认使用在线 AI 生成未审校题目。
- **存档导入与可选云同步**：先补离线导入、版本校验、冲突处理与备份预览，再评估账号。现有本机记录保持可用，云同步不成为单机前置条件。
- **关卡编辑工具**：先做给开发者使用的遭遇校验器，再评估玩家创作；需要可达性、对象预算与内容版本检查，不能仅开放坐标输入。
- **手柄与桌面封装**：纯动作先适配手柄；铭文拼写仍涉及键盘输入，交互问题明确后再决定支持方式。封装不代表目标系统已兼容。

## 7. P4：产品与发行验证

当前不开发支付。候选商业形态包括可试玩基础内容、完整章节或后续章节扩展、不影响战力的外观；教育小组使用仅作为探索方向。

| 要验证什么   | 怎样避免误判                                                           |
| ------------ | ---------------------------------------------------------------------- |
| 核心乐趣     | 先看纯动作主动重试与新打法，不能只看通关率                             |
| 铭文价值     | 分别记录开启意愿、中断感、提示依赖与延迟复测，不用题目数量证明效果     |
| 内容可持续性 | 衡量一个新遭遇的制作、校验与返工成本，不把换背景当新章节               |
| 合作价值     | 观察真实邀请和分工，不用“能连接成功”替代玩法验证                       |
| 发行条件     | 明确代码与素材许可、第三方配乐授权或替换方案，完成安装、设备与质量验收 |

项目当前没有真实用户规模、留存、收入或付费意愿数据。前期探索性访谈不用于预测收入，商业化评估在内容质量和发行条件得到验证后再开展。

## 8. 规划如何进入开发

每个候选先写目标玩家、具体场景、最小范围、依赖、验收与放弃条件；实现后才能移动到“已交付”，并附提交和证据。探索过程中发现无效的设计可撤回，不用更多功能掩盖问题。

建议顺序：**真人与品质验证 → 一个可重玩的遭遇切片 → 双角色 / 网络技术切片 → 双机合作体验 → 再决定内容规模与发行**。
