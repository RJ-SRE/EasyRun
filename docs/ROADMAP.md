# 产品路线与任务

基线：2026-10-24，PRD v0.3。以下是相对工作阶段，不是已承诺的新截止日期。早期“三天两夜”只说明需保持小范围，不能推导还有三天剩余。

## M0：可复现的当前片段

交付：当前上下路线、动作/特效、原始素材、测试、PRD、过程与 Git 流程统一保存。完成标志为干净检出可构建、当前回归通过、选定证据和提交可在远程查看。本次工作负责此阶段。

## M1：动作质量与可读性（优先）

| ID     | 任务                                 | 验收方式                                            | 主要职责         |
| ------ | ------------------------------------ | --------------------------------------------------- | ---------------- |
| MOT-01 | 精修跑步循环的前后腿、衣摆和脚底接触 | 正常速度与慢放检查，无明显跳位/滑步；与当前录像对照 | 动画/美术 + 开发 |
| MOT-02 | 调整跳跃、冲刺、落地之间的节奏       | 未出现动画锁死输入，至少三名首次玩家能完成基础组合  | 玩法设计 + 开发  |
| UX-01  | 明确可站立面、风机危险区、能量来源   | 首次试玩记录误判位置，区分操作失误与画面误导        | 关卡/视觉 + 测试 |
| FX-01  | 调整特效强度与屏幕遮挡               | 密集反馈时落点仍可见，暂停和重试无残留              | VFX + 测试       |
| UX-02  | 评估减少镜头震动与音量控制           | 选项可发现且不改变碰撞/计时                         | 产品 + 开发      |

阶段门槛：先让基础动作值得重复，避免先增加敌人、Boss、复杂剧情。

## M2：60–90 秒代表性手工关卡

目标结构：安全介绍机制 → 单一变化练习 → 两机构组合 → 可选高风险捷径 → 明确出口。保持一套核心能力，增加有区别的决策，不重复铺设同一障碍。

| ID      | 任务                           | 验收方式                                             |
| ------- | ------------------------------ | ---------------------------------------------------- |
| LVL-01  | 扩展风机/升降机构组合          | 首次、熟练和探索路线均可完成，并记录三者时间         |
| LVL-02  | 做出有代价的上层路线           | 可选目标或时间收益明确，下层路线仍成立               |
| LVL-03  | 降低重复试错成本               | 记录失败到再次获得控制的时间；决定是否需要检查点     |
| ENG-01  | 移动平台、边缘、低帧率专项检查 | 斜坡/墙体若未实现则不在关卡中暗示可用                |
| PERF-01 | 真实设备 20 分钟运行与网络首启 | 记录帧耗时分布、内存、加载时间、场景峰值；不只记均值 |
| XBP-01  | 编辑器导入、保存、重新导出     | 视口、参数、素材与玩法无意外丢失                     |

## M3：小样本可玩性验证

招募建议 5–8 位符合当前动作游戏兴趣的玩家。录制/访谈必须先获得参与者同意。只给游戏内说明，不代为演示完整答案。

记录：首次理解夺取的时刻、失败位置及原因、首次完成时间、主动重试次数、是否尝试另一条路、重试理由、最想改的一件事。自动化结果单独保存。

阶段决策不绑定未经验证的留存阈值：若多人在同处误解机构，先改表达；若能理解但不想重试，先改路线与挑战；若会主动换路线并描述明确目标，再扩展内容。样本不能证明市场规模。

## 若采用三个工作日的短冲刺

| 时段     | 聚焦                           | 当天可检查的结果                 |
| -------- | ------------------------------ | -------------------------------- |
| 工作日 1 | 动作精修、碰撞边缘、画面可读性 | M1 对照录像与缺陷清单            |
| 工作日 2 | 代表性关卡与可选路线           | 能完成的完整片段、失败分布记录   |
| 工作日 3 | 回归、性能抽查、玩家观察与整理 | 可复现试玩、证据、是否继续的决策 |

如果工作日 1 的动作基础未通过，就缩短关卡范围，不把未完成项包装成已上线功能。夜间时间只作缓冲，不依赖连续熬夜来保证验收。
