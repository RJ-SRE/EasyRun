# 三阶段背景音乐

2026-10-27，v0.15.3：修复网页菜单音乐的自动起播与中断恢复；沿用 v0.15.2 互换后的曲目。三份用户提供的 Sea Power MP3 保留原字节，不重新编码，共 34,043,869 字节，约 32.47 MiB。

## 曲目与使用时机

| 阶段 | 曲目（艺术家均为 Sea Power） | 文件 | 时长 |
| --- | --- | --- | --- |
| 开始界面 | Cleaning out the Rooms (Wandering Horn) | `public/audio/music/gameplay.mp3` | 6:27 |

每个阶段单曲循环。文件名保留初版命名，当前用途以资源清单的 stage 为准；网页映射与原生打包同步交换，未复制或改写音频。五个城区沿用同一首游戏音乐，跨区域、读取纪事不会重新起播。歌曲、原文件名、精确时长、大小和 SHA-256 见 [资源清单](../prototypes/runlab/public/audio/music/manifest.json)。这些是用户提供的第三方录音，来源与项目程序化动作音效分别记录。

## 玩家操作与节奏

- 开始页只尝试一次自动播放。浏览器允许时直接起曲；要求交互时保留「播放音乐」入口，点击菜单或按键即可启用，不必进入游戏。音频被系统挂起后也走同一恢复流程。
- 恢复判断同时检查 AudioContext 状态和媒体播放权限，不再仅凭曾经解锁就隐藏播放入口。父页面和游戏 iframe 的真实点击 / 按键都可恢复；玩家主动静音或将音乐调为 0 时不会被自动改回。
- 自动起曲仅初始化配乐通道；82 个短音效仍等首次交互再预加载。背景音乐和音效继续使用同一个宿主音频上下文。
- 「声音设置」分别调整背景音乐和音效；沿用 `belfry-audio-v2`，兼容已有偏好。默认音乐 40%、音效 85%，总输出保留现有压缩器与增益。
- 游戏暂停、铭文暂停、窗口隐藏和全局静音都会暂停歌曲并保留播放位置。继续时接着播放；返回后台前正在游戏中的，回来后仍需继续游戏。
- 铭文挑战期间歌曲按玩家设置的正常音量继续播放；进入题目和答题结束均不改变音乐音量。失败取消技能的规则不受音乐影响。
- 阶段改变先用约 180 毫秒淡出旧曲，再从新曲开头淡入。同一阶段内重试或切换城区不重播；从结束页重新开局则重新开始游戏曲。
- 音频缺失或损坏会显示「重试音乐」，游戏和其他音效仍可继续。恢复文件后可重试。

角色语音与对白仍关闭，之前删除的环境钟鸣、鼓点和技能低鼓层没有恢复。旧循环环境气流不再叠加到歌曲上；铭文聚焦和输入摩擦反馈仍属于音效总线。

## 实现与维护

`public/belfry-music.js` 维护单个隐藏的 HTMLAudioElement，设置 `loop=true`，通过 MediaElementAudioSourceNode 接到原 AudioContext 的音乐总线。长曲不进入 82 个短音效的解码缓存，不阻塞游戏资源初始化。只加载当前所需曲目，不预解码三首长曲。

phase 0 对应标题，phase 1/5 对应游戏，phase 2/3 对应结束，phase 4 保持选曲并暂停。切曲定时器与播放 Promise 使用序号防止快速切换时旧结果覆盖新阶段；同时最多只有一个媒体播放器。`soundDiagnostics.music` 提供实际曲目、播放位置、时长、循环、暂停、增益和失败状态。

本地静态服务增加 `audio/mpeg`、HEAD、Content-Length 和字节 Range 响应，支持浏览器定位及循环读取。若另行部署静态站点，也应正确提供 MP3 类型和范围请求。网页宿主使用此播放器；v0.11.3 的 `.xbp` 另行内置原生背景音乐，方式见下节。

更换曲目时同步更新播放器映射、资源清单、此文档并重跑专项测试。不要运行程序化音效生成器来重建这些第三方录音。

## XBuilder 导入包（历史 v0.11.3 接入记录）

以下保留初次接入记录。当前版本已有独立音量、原生动作音效和单词机制，现行行为以 [原生版说明](XBUILDER_NATIVE.md) 为准。

`package.py --game belfry` 将原始三首 MP3 放入 `assets/sounds/BGM_Menu/`、`BGM_Gameplay/`、`BGM_Ending/`，每首配套 `index.json`。打包前验证清单大小和 SHA-256，打包后逐文件核对 ZIP 内容；不会裁剪或重新编码交付录音。

v0.12.0 原生开始 / 暂停 / 结算界面会驱动同一套阶段音乐，菜单右上角提供可点击的音乐开关；详见 [原生导入版](XBUILDER_NATIVE.md)。

`spx/belfry/NativeMusic.spx` 在导出时合入 `main.spx` 的字段和方法区域，并在帧循环的专用标记处接入更新。使用原生 `play sound, true` 循环，阶段变化先 `stopPlaying` 旧曲；暂停用 `pausePlaying`，继续用 `resumePlaying`。默认音量 35%，B 暂停 / 恢复背景音乐，静音跨阶段保留。题目阶段不降音量；普通暂停和题目主动暂停保留音乐位置。同一阶段不会逐帧重复创建播放器，也不会因重试或换城区重播。

导入后点击舞台或按 Enter 允许浏览器播放声音。网页的淡入淡出、独立音量面板、后台自动暂停与重试 UI 没有移植到原生包；原生包切曲直接停止并切换，后台行为由 XBuilder / 浏览器自身管理。网页的战斗音效混音、词册和成就也仍在网页宿主中。原生音乐代码不进入网页生成清单，避免双重播放。

复现打包及验收（先启动本地服务，默认验收连接 4184）：

```sh
RUNLAB_URL='http://127.0.0.1:4184/' bash scripts/with-env.sh pnpm game:test:native-music
```

该命令构建、打包，并从实际 `.xbp` 解压到固定版本的 SPX 引擎中编译运行。测试通过 Web Audio 分析器检查真实引擎输出，使用响应内阶段夹具验证切换；单独以 1 秒短片段加速验证原生循环，交付包中的完整音轨保持原样。需要 ffmpeg 制作短测试片段，不需要它运行游戏。未代替线上 XBuilder 编辑器导入验收。
