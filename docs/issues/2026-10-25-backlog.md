## 1. 战斗节奏：评估连续空中普攻对下落速度的影响

### 背景

v0.5 的空中两段攻击在起手时将纵向速度至少恢复到 90，命中后还会补充上升速度。需要验证连续空挥是否让玩家长时间滞空，以及这是否削弱钩索、跳跃与落点选择的意义。

来源：[Hero.spx](https://github.com/RJ-SRE/EasyRun/blob/6c775cdbb3ba2d3dc7ea798f37f97464ff1a852a/prototypes/runlab/spx/belfry/Hero.spx)，`beginAttack` / `strike`。这是代码观察与设计待办，尚未记录专项实机复现结论。建议优先级：P1。

### 工作范围

- 用正常键盘输入分别记录不攻击、连续空挥、连续命中三种轨迹。
- 比较最短攻击间隔、空中追击次数或浮空收益衰减等方案，选定一套规则并更新 PRD。
- 保留挑空后的有效追击以及击杀接力，不让长按或连点绕过节奏限制。

### 验收

- [ ] 保存修改前后的轨迹和短录像，说明采用的节奏参数。
- [ ] 连续空挥不会无限刷新浮空收益。
- [ ] 有效空中追击、输入缓冲与冲刺取消仍可使用。
- [ ] 暂停、重开、检查点继续正确处理攻击间隔。
- [ ] 真实键盘回归与两档完整路线通过。

### 背景

范围依据：[产品路线](https://github.com/RJ-SRE/EasyRun/blob/main/docs/ROADMAP.md)、[测试记录](https://github.com/RJ-SRE/EasyRun/blob/main/docs/TESTING.md)。

### 工作范围

邀请 5–8 名未接触本项目的成年玩家，先独立游玩，再复盘。观察按住 E/松开甩出、两道钟门、Boss 破锁、受击原因以及是否主动组合攻击。记录首次求助点、失败后行为、退出位置和重试意愿。

### 验收

- [ ] 提交匿名观察表，明确实际人数、设备、游玩版本与时长。
- [ ] 只在取得同意时录屏，不在仓库上传个人信息。
- [ ] 区分操作未理解、画面未看清、理解后仍不好玩三类问题。
- [ ] 依据真实观察选出前三项改进，附对应证据并建立后续任务。

## 3. 精修战斗关键姿态的重心与动作衔接

### 背景

v0.5 新增 12 个战斗关键姿态。导入器已统一画布和脚底基准，但关键姿态图片之间的体型、衣摆和武器轨迹仍需视觉精修。构建通过不代表动作连贯性已通过真人评估。建议优先级：P2。

相关源文件：[动作导入器](https://github.com/RJ-SRE/EasyRun/blob/6c775cdbb3ba2d3dc7ea798f37f97464ff1a852a/prototypes/runlab/build-belfry.mjs)、[角色控制器](https://github.com/RJ-SRE/EasyRun/blob/6c775cdbb3ba2d3dc7ea798f37f97464ff1a852a/prototypes/runlab/spx/belfry/Hero.spx)、[素材记录](https://github.com/RJ-SRE/EasyRun/blob/main/docs/ASSETS.md)。

### 工作范围

检查地面三连、挑空接空中斩、蓄力释放、冲刺取消、受击和落地的前后帧。优先修正身体缩放跳变、脚底滑移及武器轨迹不连续；按需要精修素材、注册点或过渡帧。

### 验收

- [ ] 保存固定镜头、同一套输入的修改前后录像及关键帧对照。
- [ ] 无相邻图格残片、明显身体尺寸跳变或脚底基准突变。
- [ ] 起手、命中和收势在正常播放速度下可分辨。
- [ ] 特效不掩盖敌人预警和有效判定范围。
- [ ] 未意外改变伤害、输入缓冲和取消规则，战斗回归通过。

## 4. 建立跨浏览器与低配设备性能基线

### 背景

目前主要验证环境是 macOS ARM64 与 Chromium。已有宿主页面 rAF 采样不能直接等同于游戏引擎 FPS；Safari、Windows、低配设备和 20 分钟耐久测试仍缺证据。建议优先级：P2。

依据：[测试边界](https://github.com/RJ-SRE/EasyRun/blob/main/docs/TESTING.md)、[技术设计](https://github.com/RJ-SRE/EasyRun/blob/main/docs/TECHNICAL_DESIGN.md)。

### 工作范围

建立包含硬件、系统、浏览器版本和 Git SHA 的测试矩阵。覆盖首次加载、密集战斗、Boss/返程、反复重开、切出页面和音频恢复。至少补充 Safari、Windows Chromium 与一台可明确描述配置的低配设备；无法取得的设备标记未测。

### 验收

- [ ] 记录实际测量方法，并区分宿主 rAF、引擎帧率和长任务。

- [ ] 检查模糊/隐藏、暂停、恢复与重开后的资源释放。
