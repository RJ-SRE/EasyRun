## 已实现

- 原生游客学习按拼写/辨义分别记录次数、正确、错误、超时、辅助正确、薄弱度及复习时间；答题只更新当前词，不扫描全库。
- 当前三种拼写提示都展示过答案，成功记为辅助正确；错误 +1000、超时 +400、辅助成功 ×0.8、其他成功 ×0.4，上限 6000。
- 学习优先补未练能力，再练薄弱项，平局交替；新词首题随机，脱困优先辨义。一个词正确一次即本局已解，与长期能力分开。
- 30 词按 12 新 / 10 到期 / 6 薄弱 / 2 其他准备；同范围补足、无重复、薄弱组内加权。准备时全库分类，战斗中不重建。
- R 保留当前词组并重置本局完成；检查点继续保持；返回标题准备新词组。
- 词册提供本局薄弱筛选；每行显示“拼 / 义”状态，增加六行分页以避免释义与状态重叠。完整词库不把未知历史宣称为未学习。
- 稳定词条 ID 紧凑打包、一次建立索引；新内容导入接口与四模式分层构建路径，正式内容必须通过发布校验。
- 本地后端、XBuilder 身份验证适配器、私有 Kodo 适配器、持久化写入意图、幂等批次、签名词册准备凭证、用户隔离和参考客户端。
- `NativeCloud.spx` 原生 HTTP 客户端：准备词册、采集学习/远征事件、检查点与结算保存、冻结批次重试、保存确认、恢复已保存学习状态。测试通过真实 XGo 运行器、本机 HTTP 和本地持久化文件完成。
- 未确认记录与已确认回执分开；账号切换保留各自队列，迟到响应不能修改新账号。新运行器接管写入权须明确选择。
- 菜单、暂停与结算有保存状态；暂停/结算区分本局接触、已解、已存累计、本词库进度、待复习与通关次数。不往战斗 HUD 增加长文本。

## 同步行为与恢复入口

默认交付包没有服务地址和身份，不请求个人档案，直接按游客模式游玩。只有由正式身份入口传入已验证游戏会话后，原生同步逻辑才会启用。测试身份仅存在于自动化测试进程和内存中的源码覆盖层，不写入 `.xbp`。

- 单次请求最多等待 10 秒，失败按 2 / 5 / 15 秒间隔重试，三次之后转为手动操作；不阻塞战斗。
- `N`：在标题、暂停或结算重试保存；`G`：在标题转为游客游玩；`V`：在标题明确接管账号的写入权。已有未确认旧队列时禁止直接接管，先保留并处理旧记录。
- 原生单批最多 50 条、32 KiB；只在保存触发点冻结边界。回执到达时，仅清理被确认的队首，新产生的作答继续保留。
- 原生队列上限 2,000 条。达到上限后保留已有事件，明确提示后续练习仅本地；不会把超额作答伪称为已保存。返回标题重试成功后，重新准备下一局。
- 切换账号时旧记录只留在当前进程；最多缓存四份旧账号快照，不静默淘汰待保存内容。返回原账号后续传；刷新、关闭、重新运行仍不保证恢复未确认内容。
- 回包只包含当前 30 词的能力状态与小型汇总。完整累计次数和全历史保留在后端；本局视图与已保存汇总不互相冒充。

## 账号改名修复（local.2）

档案身份始终来自后端验证后的 XBuilder `user.id`，经固定 issuer 和持久映射密钥派生 `playerId`。用户名、昵称、登录凭证和数组序号都不参与档案 Key，也不用于查找或认领旧档案。修改名称后仍读取同一份历史；另一个账号即使使用相同用户名，也保持隔离。缺少稳定 ID 时不降级使用用户名。

这次实际修复客户端的同账号刷新行为：再次传入相同 `playerId` 时，原生端和参考客户端只更新凭证，不清空词册，不重新请求准备，不改变远征归属、事件序号或未确认队列。已经发出的保存请求可以正常确认；如果旧凭证返回 401，而当前凭证已更新，则使用新凭证重试同一冻结批次，不重新生成批次或加载词册。

仅真正不同的账号 ID 才走账号切换流程。正式 XBuilder 身份入口尚未配置，因此本次验证使用本地测试身份；交付包继续默认游客模式。测试和导入包校验见 [改名修复验收](evidence/2026-10-31-stable-identity/README.md)。
