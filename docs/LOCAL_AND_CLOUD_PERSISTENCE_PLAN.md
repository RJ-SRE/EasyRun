# 本地与云端持久化可行方案

> 2026-11-01 更新：用户后续已选择纯本地。IndexedDB 存档现已接入完整 `.xbp` 并通过故障与恢复验证，默认不启用云端；本文件保留为此前的选型记录，当前实现见 [纯本地验证版](LOCAL_LEARNING_VALIDATION.md)。

日期：2026-10-31。基于新补充的实际能力探针，本方案修正“可能需要先修改宿主才能访问本地存储”的不确定性。探针已完成，完整游戏的持久化队列尚未接入，不能把能力验证称为功能交付。

## 已验证的能力

使用 XBuilder 缓存编译器/资源（2026-10-26，SPX 3.3.0），运行最小合成 `.spx` 项目：

| 路径 | 结果 |
|---|---|
| 普通浏览器 JavaScript → localStorage | 实际浏览器进程关闭重启后读回成功 |
| 普通浏览器 JavaScript → IndexedDB | 实际浏览器进程关闭重启后读回成功 |
| `.spx` → `syscall/js` → localStorage | 游戏写入，关闭浏览器，再启动新游戏读回成功 |
| `.spx` → `syscall/js` → IndexedDB | 原生回调写入并完成事务，关闭浏览器，再启动新游戏读回成功 |
| `.spx` → `os.WriteFile` | 测试路径返回 `not implemented on js`，不选用这条文件保存路径 |

测试只操作独立生成的键、数据库及临时浏览器目录，没有读取平台账号存储。结束后删除测试数据库/键和临时浏览器目录。原生 IndexedDB 回调探针只用于能力验证；正式实现还需管理 `js.Func` 的生命周期和所有异常回调，不能直接复制探针当生产实现。

证据：[storage-capabilities-xbuilder.json](evidence/2026-10-31-xbuilder-audit/storage-capabilities-xbuilder.json)。这证明已测试的 3.3 运行器可直接调用浏览器存储，不代表所有版本、隐私设置、嵌入环境及配额条件均无差异；仍需实际发布页验收。

## 推荐方案

采用 **IndexedDB 本地待保存日志 + 现有后端/七牛云档案**。localStorage 只保存少量设置或索引，主要学习事件使用异步 IndexedDB 事务，避免频繁同步序列化较大 JSON 造成帧停顿。

```mermaid
flowchart LR
    A[游戏产生完整答题事件] --> B[IndexedDB 提交本地事务]
    B --> C[保存节点提交冻结批次]
    C --> D[后端校验并写入七牛]
    D --> E[保存确认]
    E --> F[本地事务清理已确认前缀]
```

### 本地部分

- 按固定项目标识、名称模式和规范化用户名隔离记录。不能只用原点或原始名称作为整个数据库的唯一键，避免同平台其他作品与不同档案混用。
- 本地记录包含词库/结构版本、30 词与能力视图、写入会话和代次、连续事件序号、不可变冻结批次、最后确认位置；不保存七牛 AK/SK 或平台登录 Token。
- 输入每个字母不写库；一次答题形成最终结果后，将小事件追加进异步事务。内存界面可即时更新，“本地已保存”必须等事务成功。
- 先完成本地落盘屏障，再上传被冻结批次；收到云确认后，用同一事务更新确认位置并删除已确认前缀。未确认事件不受清理影响。
- 浏览器强关后重新进入，同名首先恢复本地状态，继续使用原批次 ID。不能只恢复画面统计而重新生成事件序号。
- 空名称继续游客会话规则；是否给游客持久化另作产品决策，不自动把共享浏览器的游客历史认领给后来登录的名称。
- 配额不足、访问受限、事务失败和未知存档版本必须有明确降级状态，保留已有云记录；不假装本地保存成功。

### 云端部分

- 保留当前检查点/失败/通关/返回标题等批量保存边界，不改为战斗内逐字联网。
- 上传丢失确认时重发同一冻结批次，服务端按已有幂等规则去重；重新运行后重复上传也不能重复累计。
- 若其他设备已经接管写入、内容版本不兼容或旧会话无法恢复，保留本地队列并进入冲突处理。不能自动覆盖新云档案，也不能无条件合并旧事件。
- 本地未确认事件只存在于那台浏览器中；换设备能恢复的是七牛已确认的数据。多设备离线合并不是本方案自动具备的能力。

## 按目前部署条件分阶段

1. **先接本地持久化**：可以让 `.xbp` 在相同网站来源、相同浏览器和名称下跨运行恢复，不依赖公网后端，也不需要等待平台 ID 授权。先修复审查中的档案切换和配置覆盖问题。
2. **HTTP 云主机联调**：运行当前后端，用命令行验证接口、七牛写入和进程恢复；不把它误当作 HTTPS 发布页的可用云入口。
3. **补 HTTPS 后启用正式游戏云连接**：配置 CORS 和包内 API 地址，验证真实发布页的恢复、断网、停止/重跑、浏览器重启及重复确认。

浏览器存储按来源隔离。更换浏览器、切换站点域名/端口、隐私模式或清理网站数据，可能无法看到原来的本地记录。只有云端已确认数据可以跨这些边界恢复；本地缓存不能替代云端副本。

参考：[IndexedDB 与异步事务](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)、[存储隔离与清理机制](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)。

## 接入前需要完成的验收

真正实现时须验证：写入中强关、事务完成前强关、云确认后清理前强关、断网重启、重复批次、名称变化、访客、词库升级、配额失败、跨标签写入冲突及回调资源释放。还需测量存储事务对帧间隔的影响。本轮探针没有把这些未实现事项标为通过。
