# XBuilder 能力边界与高级二维动作游戏可行性

研究日期：2026 年 10 月 23 日。

> 历史技术研究，保留 2026-10-23 的原始讨论语境。当前产品已退出英语、语音与 AI 对话；精灵世界建议也不是现行约束。当前需求以 [docs/PRD.md](../../docs/PRD.md) 为准。下方技术观察仍对应固定版本，尚未因本次纳管而重测。

**XBuilder 可以承载具有成熟美术风格和一定动作深度的二维跑酷冒险。精确动作时序、短暂停顿、帧动画、碰撞和多层画面有可用基础；高品质仍需要自行制作角色控制器、动画资源、战斗规则与关卡工具。当前版本没有把完整的专业二维渲染和内容制作能力开放到编辑器。**

对我们的“小精灵与机器人”设想，适合优先做一个短而完整的动作关卡。可以追求类似《丝之歌》的部分视觉表达与反馈组合，但目前的证据不足以承诺相同的完整游戏品质，也不能把底层 Godot 的全部能力算作 XBuilder 的现成功能。

## 四层能力边界

| 层次 | 可以做什么 | 主要代价 |
| --- | --- | --- |
| 编辑器现有功能 | 导入造型、帧动画、声音，摆放精灵与背景，设置基础物理，写脚本，预览和发布作品 | 适合基础资产与关卡制作；许多高级参数没有可视化入口 |
| spx 脚本与项目配置 | 角色状态机、按帧调度、速度控制、碰撞层与触发器、镜头变化、克隆特效、任务规则、程序化 UI | 需要游戏程序开发；高级配置还要检查编辑器往返保存行为 |
| 自定义宿主和服务 | 语音识别、账号存档、排行榜、网络服务、外部界面 | 需要受控的游戏通信接口、异步请求、失败处理与平台适配 |
| 修改 spx 或引擎接口 | 开放自定义 shader，接入粒子、灯光、骨骼等原生能力，改变克隆限制 | 涉及 API、解释器导出、WASM 构建、资源打包和版本维护；部分功能还要增加 Godot 侧对象管理 |

XBuilder 的定位面向编程教育，但这个定位不会把作品美术限制成儿童风格。工具的具体接口和内容生产流程，才决定成人动作冒险的实现成本。[官方项目说明](https://github.com/goplus/builder/tree/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083)

## 实测结果

### 动作和碰撞

`physics-controller` 样例使用运动学角色和自写重力控制器，依次完成落地、跳跃、冲刺、撞墙、再次落地。

- 角色宽 24 个世界单位；墙中心 x 为 150，宽 10。以每秒 2400 个世界单位冲刺后，角色中心停在 x 约 132.99，符合角色右边缘接触墙左边缘的位置。
- 加入重力控制器后，落地检测为 true；起跳后为 false；随后恢复 true。
- 直接调用 `setXYpos`，可以把角色从墙左侧传送到右侧。它不能代替处理碰撞的速度移动。
- 未加控制器的运动学角色不会仅因为设置全局重力就自动完成下落。跳跃高度、可变跳跃、空中操控和冲刺结束逻辑需要自己设计。

这个结果验证了一个矩形地面和薄墙场景。斜坡、移动平台、单向平台、墙角、高速连续碰撞和不同帧率下的一致性，仍需专项测试。[物理接口](https://github.com/goplus/spx/blob/v3.3.0/sprite_physics.go)

### 动画和动作时序

- 4 帧、20 帧每秒的动画，`animateAndWait` 测得耗时约 0.20 秒。
- `stopAnimation` 后显式设置造型，等待 0.30 秒后造型仍保持。动画结束后的姿态应显式管理，不应假定永远停在最后一帧。
- `atFrame` 指定第 56 帧的回调，在第 56 帧执行。
- `script-hitstop` 样例让角色的位置与造型连续保持 3 次更新，再恢复运动。这里冻结的是自己管理的角色状态；其他脚本、物理、音频和镜头不会自动一起暂停。
- 透明度、亮度效果和镜头移动、缩放能正常运行；截图确认效果可见。镜头震动的舒适度和跟随平滑的相互影响尚未调校。

`waitNextFrame`、`deltaTime`、`currentFrame`、`atFrame` 提供了制作动作状态机的基础。输入缓存、离开平台后的短暂起跳宽限、前摇后摇、攻击取消、受击无敌和连击规则，属于我们需要编写的游戏系统。[帧接口](https://github.com/goplus/spx/blob/v3.3.0/runtime_frame.go)、[动画接口](https://github.com/goplus/spx/blob/v3.3.0/sprite_animation.go)

### 克隆和简单场景更新率

| 样例 | 观察结果 |
| --- | --- |
| 配置 30 Hz | 约 30.00 次引擎更新每秒 |
| 配置 60 Hz | 约 60.04 次引擎更新每秒 |
| 50 个运动克隆 | 约 59.99 次更新每秒 |
| 150 个运动克隆 | 约 60.02 次更新每秒 |
| 300 个运动克隆 | 约 59.33 次更新每秒 |
| 请求 350 个克隆 | 实际生成 300 个，约 59.33 次更新每秒 |
| 300 个隐藏克隆 | 仍占满克隆额度 |
| 删除其中 10 个后再次创建 | 成功补回 10 个，累计创建 310 个，存活 300 个 |

**300 是这个版本全场运行时克隆的总数上限，多个原型共享额度，也包括隐藏克隆；不是全部精灵数量的上限。** 对象池能减少反复创建和销毁的开销，但隐藏池中的克隆仍占额度。超过上限时创建被拒绝，样例没有收到明确的游戏错误。[限制及实现](https://github.com/goplus/spx/blob/v3.3.0/shape_manager.go#L36)

以上更新率用引擎帧号差除以约 3 秒墙钟时间计算。克隆只有简单 SVG 造型、透明度和位移，没有复杂物理、敌人逻辑或大纹理。它不是屏幕实际呈现帧率、长时间稳定性或手机性能基准，不能推出“300 个复杂角色也稳定 60 FPS”。

## 各类效果能达到什么程度

| 目标 | 当前可行方式 | 边界 |
| --- | --- | --- |
| 成熟风格的小精灵和机器人 | 原创高质量造型与逐帧动画 | 美术风格自由，动作一致性和帧序列需要专门制作 |
| 奔跑、二段跳、冲刺、滑行、攀墙 | 状态机、输入判断、速度、碰撞与造型切换 | 基础组件已验证；复杂动作组合要自行实现和调手感 |
| 刀光、爆点、扬尘、冲刺残影 | 特效帧动画或少量临时精灵 | 可行；粒子式精灵会消耗克隆和脚本预算 |
| 受击闪白和短暂停顿 | 亮度效果、手动姿态保持、统一游戏时钟 | 基础已验证；冻结完整战斗系统需要统一设计 |
| 镜头拉近、跟随、震动 | Camera API 加镜头脚本 | 移动缩放已验证；震动、限位和平滑组合待调校 |
| 多层森林、遗迹、远近雾和机械建筑 | 分层贴图、层级控制、根据镜头位置计算视差 | 可以形成丰富景深；不是实际三维场景 |
| 柔光、发光花粉和光束 | 绘制在素材中的光感，透明光斑和动画 | 可做风格化近似；没有验证实时照明或遮挡阴影 |
| 动态光源、法线贴图、Bloom 和全屏扭曲 | 增加或开放运行时渲染接口 | 当前编辑器和公开 Sprite 接口未提供完整工作流 |
| GPU 粒子、Spine 骨骼动画 | 预先烘焙为序列帧，或接入新的运行时能力 | 导入普通图片不会自动获得粒子模拟或骨骼混合 |
| 大型连续地图 | 分区关卡、手工管理场景状态和资产 | 存在 tilemap 数据支持，但缺少成熟的完整制作与流式加载工作流 |
| AI NPC 对话 | `ai.Player`、角色设定、上下文、注册命令和云服务 | 适合异步对话；不能把网络响应放进即时动作控制循环 |
| 英语语音控制和发音训练 | 外接 ASR、文本指令归一化及按键回退；评分另接能力 | 未发现运行中现成的语音识别或发音评分接口；编辑器录音只是声音素材录制 |
| 真正的三维跑酷 | 新增三维运行时与编辑器能力 | 当前 spx 项目和编辑流程围绕二维精灵；成本已超出普通游戏脚本开发 |

内置图形效果包括颜色、亮度、透明、马赛克、像素化、旋涡和鱼眼。底层已有 shader 机制，但高层主要把这些固定效果传入内置 shader，没有提供任意材质编辑器。开放自定义 shader 可能复用现有底层方法；GPU 粒子和灯光还需要对象生命周期与资源接口，不能只加几个脚本参数。[效果实现](https://github.com/goplus/spx/blob/v3.3.0/baseobj.go#L350)、[底层材质方法](https://github.com/goplus/spx/blob/v3.3.0/godot_modules/spx/spx_sprite_material.cpp)

## 编辑器与运行时的落差

**逻辑视口。** 当前编辑器使用固定 480×360 逻辑视口。加载时忽略自定义 `run` 尺寸，导出时重新写入固定视口；因此在外部改成 16∶9，不保证经过编辑器保存后仍保留。这不是“画面只能有 480×360 个物理像素”：浏览器画布可以缩放，运行时配置也支持其他逻辑尺寸，本次直接运行样例用了 960×540。若正式作品要 16∶9，需要明确采用自定义宿主，或修改编辑器的视口实现。[读取和导出逻辑](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/spx-gui/src/models/spx/project.ts#L449)

**碰撞编辑。** 数据模型和 spx 支持矩形、圆、胶囊、多边形等形状，但当前碰撞编辑界面对非矩形形状没有同等的操作支持。高级触发区、碰撞层与掩码更适合在配置或脚本中维护。身体阻挡、攻击命中区和受伤区应分开设计，不能把“撞墙停住”和“攻击命中通知”当作同一件事。[编辑界面](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/spx-gui/src/components/editor/sprite/PivotCollisionEditor.vue#L65)

**动画和关卡工具。** 编辑器以帧动画为主，模型明确把 `costumeSet`、`costumeMPSet`、`mAnimations`、`tAnimations` 标为未支持。tilemap 采用保留原始文件的 `DumbTilemap`；这不等于完整的可视化瓦片关卡编辑器。复杂战斗时间轴、动画事件轨道、批量关卡生产、成熟对话界面，均需要额外工作。[精灵数据模型](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/spx-gui/src/models/spx/sprite.ts#L126)、[地图实现](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/spx-gui/src/models/spx/tilemap.ts#L298)

**文档不总等于已实现能力。** 物理文档保留了历史草案，开头专门提示应以当前签名为准。对于碰撞查询、动画事件等高级功能，应核对对应版本的公开 API 和解释器导出，再运行最小样例，不能把草案表格直接作为能力承诺。[物理文档说明](https://github.com/goplus/spx/blob/v3.3.0/docs/zh/dev/engine/physic_api.md)

## 性能和加载成本

当前 Web 运行路径包含 XGo 脚本编译与解释执行、Go WASM、同步桥和 Godot WASM。精灵变换、视觉和部分物理数据采用批量同步，但这不意味着脚本运算、像素碰撞和大量临时对象没有成本。编辑器源码也说明当前运行时与编辑器共用主线程。[批量同步设计](https://github.com/goplus/spx/blob/v3.3.0/docs/zh/dev/engine/web_sync_batch.md)、[编辑器运行器](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/spx-gui/src/components/project/runner/ProjectRunner.vue#L100)

本地 `engine.wasm` 为 31.34 MiB，`ispx.wasm` 为 48.20 MiB，两者合计约 79.55 MiB。这是未压缩文件大小，既不是网络实际传输量，也不是运行内存占用。正式部署需要验证压缩、缓存、首屏加载和低性能设备的启动时间，不能用本地加载约一秒的结果宣传互联网首启速度。

一个没有主动等待的紧循环曾触发运行时超时；改为显式等待后正常。高级动作控制应按帧更新，使用时间差计算位移，避免在主线程长时间计算。视觉特效宜使用合并的动画素材、短生命周期与明确预算；不需要物理的装饰物应避免复杂碰撞。

## AI 和英语交互的真实边界

AI 模块支持角色设定、上下文和可注册命令。XBuilder 的本地源码对一次交互设置了轮次和请求超时等约束；这些机制说明它是异步服务链路，不能承担跳跃、受击和碰撞的即时裁决。任务进度、奖励与可执行动作应由确定的游戏规则检查，AI 负责表达、提示和限定范围的变化。[AI 实现](https://github.com/goplus/builder/blob/e2a4c45dfa0574ac7700fad94d2d4a6da7da8083/tools/ai/ai.go)

实际 npm 运行时测试中，显式 `import "ai"` 编译失败，改为 `import "github.com/goplus/builder/tools/ai"` 后，声明 Player 和设置角色正常。这个结果说明模块存在，也说明文档短路径与具体解释器环境之间需要适配。测试没有发送真实模型请求，尚未验证令牌、后端、响应延迟和中断恢复。

XBuilder 使用自己构建的 ispx WASM，并由宿主注入 AI 服务地址和令牌提供器。独立发布时要一起处理这些依赖，不能只复制游戏脚本就认为云端对话自动可用。

英语语音适合先用于有容错时间的交互：向机器人下令开门、选择路线、请求帮助、启动蓄力。基础跳跃和紧急闪避保留键盘或手柄路径。若要语音控制即时动作，必须测量从开口到游戏接收命令的完整延迟、误识别率和打断行为；ASR 能识别单词，不代表已经具备可靠的发音评分。

## 对我们的产品如何取舍

**第一档是可以立即押注的短篇动作体验。** 小精灵穿过被植被侵入的机器人遗迹，用精细逐帧角色、分层背景、烘焙光感、少量残影与爆点表现动作。基本跳跃、冲刺和任务互动由脚本决定，英语和 AI 放在有喘息空间的任务节点。技术基础足够，主要投入应放在控制器与美术一致性。

**第二档是可以投入研发的精品二维冒险。** 增加连招、敌人状态机、Boss 阶段、可重玩路线、完整存档与多平台适配。它需要可维护的状态机、数据驱动关卡、资源预算、自动回放测试和持续手感调校。XBuilder 可以作为基础，但现有编辑器会逐渐成为内容生产效率的限制。这里没有证据支持给出“已达到某商业游戏百分之多少”的数字。

**第三档涉及扩展工具与运行时。** 如果核心卖点必须是随角色变化的动态照明、大量 GPU 粒子、复杂骨骼混合、全屏材质效果或真正三维，应把工作量按“游戏研发加工具研发”评估。需要接入的是底层已有能力时，可扩展 spx 的接口；需要新的对象类型时，还要处理资源、生命周期和编辑器。不能用“Godot 支持”省略这些工程。

如果仍按三天两夜的原始周期，应把目标限定为一个可玩的完整片段：一名角色、三种核心动作、一条短路线、一个敌人或机关、一个英语任务。不要同时承担骨骼系统、动态图形管线、多平台正式发布和开放式 AI 剧情。

## 进入正式开发前的验收门槛

下面是建议的验证顺序，不是已经完成的验收结果。

1. 制作 60 至 90 秒有代表性美术和特效的动作片段，确定角色的跑、跳、冲刺是否值得反复玩。独立测试输入缓存、墙角、移动平台和不同帧率。
2. 在实际目标桌面浏览器和至少一台目标手机上测帧耗时分布、输入响应、峰值内存、加载时间，并连续运行 20 分钟。桌面以稳定 60 FPS 为目标；手机目标需结合实际设备确定。
3. 把攻击命中、冻结、角色动画和敌人状态统一到可控时间逻辑中，验证暂停和恢复没有错位。给敌人、子弹与视觉特效分别分配克隆预算，预留峰值余量。
4. 验证 XBuilder 工程导入、编辑、保存、重新导出后的尺寸与高级配置；然后只挑一个计划发布的平台完整打包。
5. 最后接入语音和 AI，测弱网、无麦克风、请求失败和对话被打断时的体验，再判断它们是否增加乐趣。

如果动作片段好玩、目标设备性能达标，继续用 XBuilder 是合理选择。如果作品的差异化主要依赖当前未开放的渲染能力，宜在扩大关卡和美术生产前比较扩展运行时与改用完整引擎编辑器的成本。

## 复现与文件

在项目根目录执行：

```sh
bash scripts/with-env.sh node research/xbuilder-boundaries/make-cases.mjs
bash scripts/with-env.sh node research/xbuilder-boundaries/run-probes.mjs
bash scripts/with-env.sh node research/xbuilder-boundaries/make-followups.mjs
bash scripts/with-env.sh node research/xbuilder-boundaries/run-probes.mjs followup-cases.json followup-results.json
bash scripts/with-env.sh node research/xbuilder-boundaries/run-probes.mjs ai-qualified-case.json ai-qualified-result.json
bash scripts/with-env.sh node research/xbuilder-boundaries/analyze-results.mjs
```

- `projects/`：可读的 `.spx` 与资源文件。
- `packages/`：对应的 `.xbp` 项目包；运行时测试已完成，完整编辑器导入操作未测试。
- `results/probe-results.json`：第一组 8 个场景的原始日志。
- `results/followup-results.json`：控制器、克隆回收、AI 短导入和角色冻结结果。
- `results/ai-qualified-result.json`：完整 AI 包路径的运行结果。
- `results/summary.json`：计算方法、更新率与 11 项断言。
- `results/*.png`：运行画布截图，使用几何占位素材验证功能，不代表最终美术。
- `results/pilot-tight-loop.json` 和 `results/invalid-config.json`：初始紧循环与错误物理配置的诊断记录。物理配置修正后重新运行通过，不能把早期配置错误归因为运行时不支持按帧等待或自定义尺寸。

研究执行当时未改动旧归档和远程；2026-10-24 的 Git 纳管另见开发日志。
