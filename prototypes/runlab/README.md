## 两个原型分别在验证什么

**盗速者**：移动运输车是真实的动能来源，吸取后车辆暂时减速，角色获得一次冲刺飞跃。三处断桥需要连续捕获和释放动能；浮空平台提供尝试不同落点的空间。本机最快通关时间鼓励路线优化。

需要观察：玩家是否理解“偷走物体的速度”，是否主动试不同的释放时机，通关后是否愿意再跑。只有三次固定接力的版本，还不能证明长线关卡深度。

**一镜到底**：木箱、横梁和断口构成两组三段动作。普通跳跃能通过木箱；翻越、滑行、空中特技能完成六个镜头并积累连贯分。失败即时重拍。翻越有贴合箱顶的辅助，降低输入时机过于苛刻造成的挫败。

需要观察：玩家是否为了动作完整而主动重玩，还是只在意到终点。目前没有录像回放、自由招式系统或分享功能，不能据此断言具有传播效果。

建议先让 5—8 位目标玩家各玩两款，交替先后顺序，只提供页面上的提示。先记录首次成功、失败位置、主动重试和结束反馈，再访谈“你为什么又玩了一次”。小样本只用于淘汰明显无趣或难懂的机制，不用于估计市场规模。

## 工程结构

- `build-games.mjs`：生成两款游戏的关卡、原创 SVG 素材及 spx 源码，是玩法修改入口。
- `projects/velocity/`、`projects/cinema/`：生成的完整 spx 工程；下一次生成会覆盖这些文件。
- `public/`：试玩页面、交互提示、音效、本机记录，以及提供给运行时的工程 JSON。
- `server.mjs`：只提供试玩静态文件与本机已安装的 `@xgo-pkgs/spx` 运行时。
- `playtest.mjs`：实际浏览器键盘通关与回归检查。
- `package.py`：按 XBuilder `.xbp` 格式导出工程。
- `exports/velocity.xbp`、`exports/cinema.xbp`：工程包，不包含网页外壳和本机成绩记录。

核心移动、碰撞、动能、计时和计分均在 spx 中运行；网页负责中文界面、声音和存储。角色采用自定义平台动作控制器，未启用引擎刚体物理。内部画面为 960 × 540；网页等比缩放。

`.xbp` 已验证 ZIP 完整性及文件结构，但未在完整 XBuilder 编辑器中重新导入测试。完整试玩体验以本地页面为准：工程包自身不含网页结算界面，编辑器保存也可能改变视口配置。
